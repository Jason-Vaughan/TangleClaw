## 2026-11-02 — v5.55.0 W2-REC: reconcile checkout ownership and the live install

<!-- prawduct: type=internal | scope=v5550-w2-rec -->

- Reconciled Wave 1 PRs #2803 (#1267), #2804 (#1672), #2806 (#1710), and #2811 (#1332, #1977). GitHub REST confirmed all five Milestone #40 issues closed, and #2811 landed as a two-parent merge commit. Their accepted `changelog.d/` fragments remain the release-note inputs.
- **Checkout retirement and server identity (#1267, #1672):** a dry-run-first tool retires only eligible inactive worktrees and `[gone]` branches, rechecking before removal. The server reports coupling for the checkout whose code it actually runs; a separate CLI can provision a dedicated checkout and repoint a validated launchd plist. Neither workflow changes the live install merely by being merged.
- **Stale-install response (#1710):** classification reuses the existing restart-impact rules. Automatic records-only fast-forward requires a clean `main`, a verified exact-SHA delta, and no wrap in flight. Executable or mixed changes yield an operator-coordinated restart decision; unknown changes await diagnosis. Route and poller wiring remain follow-on work.
- **Worktree and branch ownership (#1332, #1977):** both are standalone deterministic module APIs with callable ownership, admission, and invalidation helpers ready for host integration. The worktree API uses gitdir markers and content baselines for fail-closed write admission. The branch API tracks an owner generation, publication-checked handoff, and exact-head review evidence invalidated on rewrite; its cross-owner mutation and force-push checks refuse those actions when called. Live command, write, and push paths do not invoke these APIs yet.

## 2026-11-01 — v5.53.0 W2-REC: reconcile Master authority and session lifecycle records

<!-- prawduct: type=internal | scope=v553-w2-rec -->

- **Master lifecycle authority (#2132, #966):** the existing `read-only`/`suggest`/`write` level determines a generation-tracked lifecycle toggle, with only `write` granting fleet-lifecycle mutation. A verified Operator can change it through `POST /api/master/authority` or the guarded config PATCH; both paths require Operator proof. The Master's own lifecycle calls require its scoped `tc_master_` token, a current generation, and an allowlisted action.
- **Session mutation boundary (#2129):** launch and kill admit the Operator or an authorized Master, never a project's own session. Wrap routes also admit the project's current verified session acting on itself, but never another project's session; each route checks the caller independently of the general launch-binding floor.

## 2026-11-01 — W2-A: HEAD-as-GET, dashboard poll latency, Caddy Drift route wiring, Tailscale origin (#923, #2771, #1415, #1380)

<!-- prawduct: type=feature | scope=w2a-923-2771-1415-1380 -->

- **HEAD-as-GET (#923):** `HEAD` now answers exactly what `GET` would (status, headers, no body) via one `dispatchMethod` variable at every routing comparison plus a response-body-suppression wrapper at `handleRequest`'s shared exit point, rather than touching each scattered `GET`-gated site individually. The two reverse-proxy sections (`/terminal/*`, `/openclaw[-direct]/*`) are deliberately untouched — they forward whatever method arrives to a different process.
- **Dashboard poll latency (#2771):** `lib/projects.js#listProjects` caches each project's facts for 20s, skipping the scanner-child read on a warm hit while leaving the existing one-at-a-time spawn discipline for a cold/stale one unchanged. `public/landing.js#loadProjects` fetches `/api/projects` and `/api/awareness` in parallel (decoupled, not `Promise.all`, so a stalled awareness poll never blocks the project list from rendering) and shows a toast on a failed fetch instead of returning silently.
- **Caddy Drift route wiring (#1415):** `POST /api/caddy-drift/resolve` wires W1-A's Resolve/Acknowledge menu — `restore-baseline` reuses the credential route's fail-closed write-then-validate-then-restore idiom; `acknowledge` updates module-level state in `lib/server-info.js`, gated through `lib/caddy-drift.js#shouldShowDrift` on every read. Behind `signedInOperator`.
- **Tailscale origin wiring (#1380, partial):** the plan-share-link route advertises the resolved Tailscale origin when `config.tailscaleMode` is on, honestly reporting `origin: null` with a reason rather than silently falling back to Host-header addressing. Session-start links and Medusa peer-advertisement text are genuinely out of scope (Ruling A490-W2A-R3): both stay loopback-only by design.
- **Pre-merge fix, Architect Ruling A490-W2A-R6:** `tc whoami`/every `bin/tc` verb transitively required this PR's new top-level `require('./caddy-drift')` in `lib/server-info.js`, which requires `./store`, loading `node:sqlite` and printing an `ExperimentalWarning` to stderr — breaking `test/tc-pane-identity.test.js:504`'s stderr-emptiness assertion on CI. Root cause independently verified against the actual require chain (not taken on citation alone) before fixing; `./caddy-drift` is now lazy-required inside `_visibleCaddyDriftNotice()`'s existing null-guard, matching this file's own `./bind-policy` precedent. `test/tc-pane-identity.test.js` is untouched (115/115 pass); a 129-file `server.js`-dependent regression sweep ran clean (4502/4502).
