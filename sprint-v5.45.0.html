⚠️ What Didn’t Work & Proven Fixes for v5.46.0

  • 1. Extracting a Helper Out of server.js Requires Updating Architectural Source-Guard Tests (PR #2680, Finding W1-F1_v545)

    In W1-A (#2680, #1284), extracting expandHomePath() from server.js into lib/tangleclaw-home.js caused test/primary-checkout-guard.test.js to fail in CI because its static GUARD_SOURCES array scanned server.js and lib/routes/setup.js for os.homedir() + .tangleclaw. Fixed in R2 (cc6a5d4b) by adding path.join('lib', 'tangleclaw-home.js') to GUARD_SOURCES. Fix / Guardrail for v5.46.0 (P25): Whenever a car extracts code out of server.js into a lib/*.js helper, require Builders to run grep -rn "server.js" test/*guard*.test.js test/*consistency*.test.js before pushing R1.

  • 2. Tightening store.projects.add() / update() Option Keys Exposed 10 Legacy Test Callers Passing Out-of-Schema Keys (PR #2682, Finding W1-F2_v545)

    In W1-B (#2682, #1225), rejecting unknown option keys at the store.projects.add() / update() boundary immediately caught 10 existing test files passing out-of-schema keys (team, mode, methodology, directive) that belong in .tangleclaw/project.json rather than SQLite. PM + Architect co-signed an immediate scope expansion for those 10 test files and filed #2681 for a production caller in lib/projects.js:491. Fix / Guardrail for v5.46.0 (P26): When a car tightens a core store/API validator to fail-closed, pre-scan test/ callers during Charter drafting so legacy test callers are included in the car’s initial file scope.

  • 3. Two Wave 1 Cars Touching server.js (W1-A + W1-D) Caused the Sprint’s Single Same-Wave Rebase (PR #2680, Finding W1-F3_v545)

    Although W1-A (#2680) only touched 1 line of server.js (importing expandHomePath) while W1-D (#2679) touched PUT /api/projects/:name in server.js, both cars modified server.js and .prawduct/change-log.md, requiring W1-A to rebase once onto b68119e8 after W1-D merged. Fix / Guardrail for v5.46.0 (P27): Strictly enforce the W1-F1_v542 rule that at most 1 car per wave may touch server.js, and prohibit .prawduct/change-log.md edits in all Wave 1–2 cars without exception.

  • 4. GitHub Multi-Issue Closes #A, #B, #C Syntax Only Auto-Closes the First Issue (Finding W2-F1_v545)

    When PR bodies or commit messages write Closes #1289, #1288, #2216 on a single comma-separated line instead of repeating the keyword (Closes #1289, Closes #1288, Closes #2216), GitHub only auto-closes the first issue on merge, leaving #1288, #2216, #2180 open until PM closed them via gh issue close with PR links. Fix / Guardrail for v5.46.0 (P28): Require every multi-issue PR body to repeat Closes #N before each issue number and verify gh issue list --milestone <title> --state open immediately after Wave 2 merges.
