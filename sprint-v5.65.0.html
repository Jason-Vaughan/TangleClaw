📖 Plain-English Summary — What Sprint v5.65.0 Accomplished & Why It Matters Written for operators, stakeholders & non-specialist readers

Native Linux / systemd Host Support, Cross-Project Version Dependency Registry, Control-API Hold/Prune Hardening, and Full CLI/Server/Store Runtime Wiring

Sprint v5.65.0 (“Linux hosts”) opens our Two-Version Autonomous Sprint Train (v5.65.0 → v5.66.0) by shipping first-class Linux / systemd service management, tracking cross-project version dependencies, hardening coordinator hold/prune state in the Control API, and mounting ten previously staged Slice 1/2 governance, documentation, and store modules directly into live CLI verbs, server routes, and store boot hooks across 12 active issues and 5 pull requests (+4,168 / -75 feature LOC):

1. Native Linux / systemd Host Support & Cross-Project Version Dependencies (`#1424, #777`)

Car 65-A (PR #2899) enables TangleClaw to run natively on Linux hosts via generated systemd --user / system unit files, loginctl enable-linger provisioning, and journalctl diagnostics (lib/linux-systemd.js, #1424), and adds a cross-project version dependency registry (lib/project-version-deps.js, #777) that automatically notifies dependent projects when an upstream project cuts a release.

2. Control-API Hold/Prune Fixes, Merge-Role Guard Hooks & Server/CLI Mounting (`#2832, #2834, #2866, #2887, #2878, #2883, #2877`)

Car 65-B (PR #2900) blocks peer-pause-request from bypassing /pause's nudge+escalation flow (#2832), fixes a tie-breaking bug in coordinator_roles retention pruning (#2834), and wires merge-role-guard launch PATH hooks and AskUserQuestion auto-handling into lib/sessions.js (#2866). Car 65-C (PR #2902) mounts tc manual / tc docs route (#2887), tc merge check + GitHub required status publishing (#2878), scheduled scorecard-producer refresh (#2883), and live roadmap admission/sync (#2877).

3. Async Projects I/O, Store Master-Authority / Medusa Sync & Shared-Docs Fleet Provisioning (`#2864, #2871, #2870`)

Car 65-D (PR #2901) migrates synchronous filesystem calls in lib/projects.js to lib/projects-async-io.js and wires workspace-rename-check into session briefings (#2864), wires PM Medusa toggle reconciliation, scratch-home defaults, and legacy master-authority repair into lib/store.js (#2871), and wires sharedDir auto-creation, MagicDNS HTTP serving, and fleet provisioning (#2870).

What Worked Exceptionally Well — Validated v5.65.0 Architectural & Process Wins

1. Clean Separation of Code-Complete Linux / systemd Support (`#1424`) from Physical Linux Hardware VRF (`#1564`)

By scoping `Car 65-A` (`PR #2899`) to deterministic `systemd --user` / system unit generation, `loginctl enable-linger` orchestration, `journalctl` status parsing, and full mock-driven unit tests (`test/linux-systemd.test.js`) while deferring physical Linux host verification `#1564` to `Milestone #54` (`v5.67.0`) under `A185`, `#1424` shipped cleanly without blocking on external hardware.

2. Closing Both Control-API State Edge Cases (`#2832, #2834`) Alongside Slice 2 Merge-Role-Guard Wiring (`#2866`)

`Car 65-B` (`PR #2900`) paired the two surgical Control-API fixes — rejecting `peer-pause-request` on the generic hold route so peers must use `/pause`'s nudge+escalation flow (`#2832`) and adding `id DESC` tie-breaking to `coordinator_roles` retention pruning (`#2834`) — with Slice 2 launch PATH/shell hook injection for `lib/merge-role-guard.js` (`#2866`).

3. Four-Ticket CLI & Server Mounting in `Car 65-C` (`#2887, #2878, #2883, #2877`)

Consolidating all `bin/tc.js`, `lib/tc-verbs.js`, and `server.js` governance/doc/scorecard/roadmap wiring into `Car 65-C` (`PR #2902`) eliminated cross-car conflicts on `server.js` and `bin/tc.js`.

4. Consolidating Projects Async I/O (`#2864`), Store Repair (`#2871`) & Shared-Docs Serving (`#2870`) in `Car 65-D`

Grouping all `lib/projects.js`, `lib/store.js`, and `lib/shared-docs*.js` runtime wiring into `Car 65-D` (`PR #2901`) kept `Car 65-D` 100% file-disjoint from `Cars 65-A/B/C`.

What Didn't Work & Concrete Guardrail Fixes Enacted in v5.65.0

1. Physical Linux Host / External Repo Blockers Sitting Inside Active Sprint Milestones (`#1564, #2347, #2258`)

Three issues originally sitting in `v5.65.0`/`v5.66.0` (`#1564` physical Linux host VRF, `#2347` external `Jason-Vaughan/Medusa#67` dependency, and `#2258` Operator Vercel dashboard setting cutover) required external hardware or Operator credentials. Fix / Guardrail: Re-homed `#1564`, `#2347`, and `#2258` to `Milestone #54` (`v5.67.0`) at Gate 0 under `A185` (`Guardrail 09`) so `Milestones #50` and `#51` contain 100% repo-deliverable issues.

2. Timestamp Tie Ambiguity in SQLite Retention Queries (`#2834`)

When two `coordinator_roles` rows shared the same millisecond `created_at` timestamp, `ORDER BY created_at DESC` without a secondary key could evict the newly inserted row during retention pruning. Fix / Guardrail: Always include a monotonic tie-breaker (`ORDER BY created_at DESC, id DESC` or `rowid DESC`) in SQLite retention and pagination queries.

3. Synchronous Filesystem Calls Remaining in `lib/projects.js` After Helper Extraction (`#2864`)

Extracting `lib/projects-async-io.js` in Slice 1 left synchronous `fs.*Sync` call sites inside `lib/projects.js` until Slice 2 (`#2864`). Fix / Guardrail: Pair async I/O helper extraction with call-site migration tests that assert zero blocking `fs.*Sync` calls on hot request paths.

4. Shared Registry File Contention (`docs/areas.json`, `.testament.toml`, `test/tiers.json`) Across 4 Parallel Cars

Adding new test files across all 4 cars required serialized ancestor syncs at merge time. Fix / Guardrail: Keep registry arrays alphabetically sorted and perform an immediate `git merge origin/main` before each serialized PR merge.
