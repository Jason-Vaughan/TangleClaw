5. Sprint Post-Mortem: What Worked vs. What Didn’t (A476 & Obsr)

Candid synthesis by the Project Manager (PM-CONTINUITY-G2), Architect (A476), Integrator (TC-Lane-INT), and Sprint Observer (TC-Lane-Obsr) of what succeeded and the concrete process/tooling bottlenecks uncovered during v5.41.0.

✅ What Worked Exceptionally Well (Keep & Codify)

  • 1. Disjoint Merge Pipelining (v5.40.0 Finding W1-F1) Cut Total Sprint Wall Time by 70% (10h 06m → 2h 57m) When PR #2647 (W1-B) merged at 21:02:28Z, PR #2646 (W1-A) was 100% file-disjoint and reported mergeable: MERGEABLE. Instead of forcing TC-Lane-A to rebase and reset its 12-minute CI run + exact-head review stamps, TC-Lane-INT merged #2646 directly 5 minutes 18 seconds later at 21:07:46Z.
  • 2. Dual Codex PR Reviewers (PRR-A & PRR-B) Averaged ~1.5m per Review Turn While Catching 6 Real Edge Cases Empirical timing proved that PRR is not the merge bottleneck: each review round completed in 70–110 seconds while catching 6 real pre-merge bugs: (a) #1321 calling warnStaleWrap before rotation/opt-in/listener/observeOnly gates in lib/medusa-wake.js; (b) #1757 archivedBareFilename false-matching a live activePlan when an archive file shared the same basename; and (c–f) four subtle process-group termination edge cases in #1503 (unconfirmed group-kill resolution, maxBuffer overflow group-kill, 2s deadline groupKillConfirmed: false surfacing, and SIGTERM-trapping child exit classification) plus #1733 gating rm -f on a successful cat read.
  • 3. Immediate Slot Reuse on TC-Lane-C Landed Wave 2 (W2-A #2648) in 26.4m Build Time While Wave 1 Was Still In Flight Rather than waiting for all four Wave 1 cars to finish before dispatching Wave 2, freeing TC-Lane-C immediately after W1-C (#2640) merged at 20:04:36Z allowed W2-A (#2648 — #670, #1782) to build in 26.4m and merge at 20:45:22Z — ahead of W1-B, W1-A, and W1-D.
  • 4. Permanent Roadmap Board Resilience & Automatic LANE_QUEUE.md → stage:claimed Sync + Issue #2644 Fixed transient GitHub API HTTP 408/429/5xx refresh failures in build-board.py and sync-board.sh (175/175 tests passing), updated reconcile-milestones.py to parse LANE_QUEUE.md and automatically apply stage:claimed (In Progress) to all dispatched wave issues, and filed Issue #2644 to bring native sprint wave orchestration into TangleClaw.

⚠️ What Didn’t Work & Proven Fixes for v5.42.0

  • 1. Unsolicited Builder Rebase on W1-D (PR #2641) After #2646 Merged Cost 18m of Redundant CI & Re-Stamping (Finding W1-F1_v541) Even though PM and Integrator adopted the disjoint no-rebase rule at 21:02Z, TC-Lane-D independently rebased #2641 from 474a91dd onto b204edd3 (producing 23fcb949) right after #2646 landed. Because Rule #282 binds merge authorization to the exact head SHA, #2641 had to wait 12 minutes for CI run 40585900031 and fresh PRR-B + A-Gate re-stamps. Fix for v5.42.0: Add an explicit Builder rule forbidding Builders from rebasing an open PR once R-Gate ACCEPT + A-Gate APPROVED are stamped unless instructed by TC-Lane-INT or TC-Lane-PM due to an actual merge conflict (mergeable: CONFLICTING).
  • 2. 4 Review Rounds on W1-D (PR #2641) for #1503 Process-Group Termination State Machine While PRR-B and TC-Lane-Arc caught 4 genuine edge cases in lib/exec.js (awaiting group-kill confirmation before resolving, killing the process group on maxBuffer errors, surfacing groupKillConfirmed: false at the 2s deadline, and preserving timedOut: true via _armGroupKillTimeout.fired() when a child traps SIGTERM and exits 0), specifying those 4 state-machine invariants in Charter A476 upfront would have converged W1-D in 1 round instead of 4. Fix for v5.42.0: Include explicit state-table invariants in the Sprint Charter for any issue touching OS signals, child process lifecycles, or timers.
  • 3. 100KB Single-Call HTML Generation Triggered 5-Minute LLM Stream Timeout on TC-Lane-Obsr (Finding W4-F1_v541) When generating the ~65 KB 7-section interactive HTML report (v5.41.0/index.html), emitting the entire HTML document inside a single write_file or giant heredoc tool call exceeded the 5-minute LLM output stream timeout on TC-Lane-Obsr. Switching to a chunked Python generator script (/tmp/generate_v541_obsr.py) produced all HTML, Markdown, and JSON artifacts in under 2 seconds. Fix for v5.42.0: Codify a permanent Python template generator for P4 sprint reports so no agent ever streams >15 KB of raw HTML in a single tool call.
  • 4. Medusa BLOCKING_LIMIT (5) & Single-Argument tc message close Syntax tc message send --priority blocking enforces a cap of 5 concurrent open blocking exchanges (HTTP 429 BLOCKING_LIMIT), and tc message close <id> only closes the first argument when multiple IDs are passed on one line. Fix for v5.42.0: Always close completed exchanges immediately via a shell loop (for ex in ...; do tc message close "$ex"; done).
