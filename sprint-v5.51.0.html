📖 Plain-English Summary — What Sprint v5.51.0 Accomplished & Why It Matters Written for operators, stakeholders & non-specialist readers

Guaranteed Startup Rule Delivery, One-Step Operator Rule Edits, and Feature-Index Stub Clocks

Autonomous AI coding sessions rely on project rules to know their boundaries and workflow. Before v5.51.0, if a startup hook failed to fire or a project added its very first rule after launch, a session could miss its rules until restarted—and editing an active rule required a multi-step dance. Sprint v5.51.0 (“Prime and rule delivery”, Leg 2 of our back-to-back dual sprint) closed 5 issues across 6 pull requests (+3,232 / -144 LOC):

1. Automatic Startup Rule Redelivery (`#1176`) & Dynamic Hook Slot Growth (`#2293`)

When a session launches or clears, TangleClaw now watches for the startup rule hook’s cryptographic receipt. If that receipt never arrives within the expected window, lib/rule-receipt-redelivery.js automatically re-delivers the startup rules over the open channel (`#1176`). And when a project refreshes its rules after adding new ones, refreshProjectRules dynamically grows the project’s registered hook slots (`#2293`) so new rules take effect on `/clear` without needing a full session relaunch.

2. One-Step Operator Rule Edits (`#2325`) & Unified Usable-Rule Checks (`#1654`)

Operators can now edit an active session rule in a single step in the Project Rules modal (`#2325`), with the server atomically superseding the old rule revision and refreshing live sessions. We also unified the isUsableRule predicate across launch-drift detection, rule channels, and wrap steps (`#1654`) so empty or retired rules are filtered identically everywhere.

3. 14-Day Auto-Stub Clock Census (`#1196`) & Cross-Sprint Pipelining

lib/feature-index-prime.js now tracks the age of every `## TODO (auto-stubbed )` block in `FEATURES.md` and surfaces a 14-day stub-clock countdown in session primes (`#1196`). Even better, all 3 feature PRs in `v5.51.0` were built in parallel while `v5.50.0` Wave 2 was running, allowing `v5.51.0` Wave 1 to merge minutes after `v5.50.0` deployed.

What Didn't Work — Frictions & Concrete Guardrail Fixes

1. Static Regex Scanner in test/tmux-draft-capture.test.js Matched sendKeys( Inside a JSDoc Comment (#2759)

In `PR #2759` (`62ae6e2d`), `lib/rule-receipt-redelivery.js` had a JSDoc comment containing `` `tmux.sendKeys(...)` ``, which `test/tmux-draft-capture.test.js:563`’s raw source regex matched as a call site missing `engineId`. Fix / Guardrail: Fixed in `e89a3d33` by removing the trailing parentheses in the JSDoc comment, and added a guardrail to run `node --test test/tmux-draft-capture.test.js` whenever a file mentions `sendKeys`.

2. Idle Codex Sessions Showed engine-thread-unknown for Medusa Wakes Immediately After Server Restart

After `com.tangleclaw.server` restarted on `:3102` for the `v5.50.0` deploy (`PID 92580`), idle Codex sessions (`TC-Lane-PRR-B`, `TC-Lane-PRR-A`) reported `engine-thread-unknown` until they executed a turn because the restarted server had not yet observed a fresh thread event. Fix / Guardrail: After any live server restart during an active sprint, send a 1-line `tc message read` prompt wake to idle Codex reviewers so their thread state re-registers immediately.

3. Pairwise git diff --name-only origin/main...HEAD Included Inherited History Before Merge-Base

An initial pairwise overlap check on `PR #2759` ran `git diff --name-only` across commits prior to `PR #2759`’s merge-base (`309dacbd`), falsely flagging `lib/sessions.js`. Fix / Rule: `TC-Lane-Arc` (`Ruling A489-W1-HUNK-DISJOINT-R2`) and `TC-Lane-INT` verified the true PR delta (`git diff --name-only $(git merge-base origin/main HEAD)..HEAD`), confirming `#2759` touched 0 overlapping code files.

4. Cold /api/usage/windows Scan Latency Exceeded 10s Default CLI Timeout (#2766)

During post-deploy verification, `GET /api/usage/windows` returned HTTP `200` with all expected fields in `24.7s`, exceeding `bin/tc`’s default `10s` client timeout for `tc usage windows`. Fix / Guardrail: Filed Issue `#2766` to cache/warm the usage-windows snapshot or extend the `tc usage windows` timeout in `v5.52.0`.
