## Release scope and gates

The five accepted `changelog.d/` fragments for #1176, #1196, #1654, #2293, and #2325 were compiled into the dated `[5.51.0]` section and removed. `version.json` is the repository's version source. `scripts/release-prepare.js` updates the README clone pins and extends the released-section lock. This repository has no `package.json` or `package-lock.json`.

The initial W3-REL head `570003af` passed the Stage 3 Testament pool (5,891 passed / 2 skipped), Stage 4 pool (5,817 passed), and exact-head GitHub Actions Tests. Stage 5 reported 13 container failures. Ten are the five environment-assumption files tracked by #2758: `test/rule-delivery-receipt.test.js`, `test/setup-wizard.test.js`, `test/tmux.test.js`, `test/tmux-named-paste-buffer.test.js`, and `test/update-release-link.test.js`. Three additional cases in `test/rule-receipt-redelivery.test.js` exercise receipt POST, token stamping, and token deletion. The hook intentionally skips those operations when `curl` is unavailable; the Testament container image does not install `curl`, while the host does. A targeted pool run passed 51 and failed those 3; the same file passed all 54 on the host. Architect ruling `A489-W3-STAGE5-CURL-R2` treats the three as the same #2758 missing-curl container residual and accepts them for this release. The container package gap remains a follow-up, not a claim that Stage 5 passed.

Rule delivery on a running Claude session depends on its hook configuration being read after the file-change settle interval; a zero-delay scripted `/clear` is not guaranteed. Engines without a `SessionStart` hook still receive a newly approved rule on next launch or immediately through `tc rules`. Receipt redelivery is bounded and escalates when confirmation remains absent.
