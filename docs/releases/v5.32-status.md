## Upgrade rehearsal

Run on 2026-10-11 at 17:11 PDT, in isolation, at commit `3827f75a` of the release pull request, and repeated with fresh copies of the first two stores at its final commit `dab3fa9f`, with the same results. The commits between them change only this document.

Three real stores from this host were copied with `sqlite3 .backup` into a scratch directory, and each copy was opened by the candidate's own `lib/store.js` with its base path set to that directory. The live server, its database and its log were not touched.

| Store copied | Schema before | Schema after | Integrity | Foreign-key violations | Bridge schema problems | Tables lost | Row counts changed |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| A backup of 2026-09-13 (22 tables, 8,861 rows) | 37 | 63 | ok | 0 | none | none | only `schema_version` |
| A backup of 2026-10-09 (63 tables, 240,548 rows) | 57 | 63 | ok | 0 | none | none | only `schema_version` |
| The live store, copied at the rehearsal (67 tables, 259,863 rows) | 63 | 63 | ok | 0 | none | none | none |

Opening the upgraded schema-57 copy a second time changed nothing. In it, `bridge_outbound` holds 116 rows, `sessions` 1,309 and `projects` 90, the same as in the backup it was copied from.

**Why no server was started on a copy.** A TangleClaw server started on a copy of the live store would read the live sessions from it and run its monitors against the real tmux panes of this host. The server's start on this code was instead observed on the live install on 2026-10-11 at 16:21 PDT (`85b6b501`, which differs from this release only by documentation and the version number): healthy in three seconds, schema 63.
