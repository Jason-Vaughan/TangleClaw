# v6.2.9 — Switchboard traffic Under the Hood, a Medusa indicator, chat polish and Medusa fleet isolation

TangleClaw v6.2.9 is a release on top of v6.2.8, from the operator's live walkthrough and from observed CI timeouts and cross-fleet Medusa traffic. The v6 chat moves switchboard traffic out of the conversation and gains a Medusa indicator, a multi-question "Waiting on you" queue, message tints, a footer status bar, a slimmer header and support for long prompts. Medusa messaging stays inside the sender's fleet, and the CI test job gets a longer limit.

## Changed behaviour: Medusa fleet isolation

Read this before upgrading if your projects message each other across project groups.

- **Medusa messaging stays inside the sender's fleet** (#3077, tests in `test/api-medusa.test.js` and `test/medusa-startup-announce.test.js`). A project's fleet is its project groups plus its tags. Two projects share a fleet when they share a group or a tag. Projects with no group and no tag share one default pool, so an install that uses no groups works as before. A grouped project and an ungrouped one never share a fleet.
- A project's send outside its fleet is refused with `403 CROSS_FLEET_FORBIDDEN` unless it carries `allowCrossFleet: true`. A project's roster lists its own fleet plus the Master, and `?scope=all` lists every fleet. A coordinator's broadcast reaches its own fleet by default; reaching every fleet needs `scope: "all"` with `emergency: true` or `confirmAllFleets: true`. Startup announcements only wake coordinators in the announcing project's fleet.
- The Operator and the Master are exempt throughout. The Master and the operator bridge stay reachable from every fleet, whether or not their listener is running, so a project can always answer the Operator.
- Tags count as fleet membership, so two otherwise unrelated projects that share a tag are in one fleet. Callers that name no project (the Master's own mount, the operator-bridge gateway and the check-watch sender) are not fleet-scoped.

## Added (filed as Fixed)

These are new features. To keep the v6.2.x patch train they are filed under Fixed, so this release is the patch 6.2.9 rather than 6.3.0.

- **Switchboard traffic Under the Hood and a Medusa indicator** (#3076, tests in `test/v6-b1-ui-shell.test.js` and `test/v6-browser-shell-and-conversation-e2e.test.js`): `[TangleClaw Switchboard]` wake notices are typed into the session's pane, so the chat showed them as messages from the operator. Recorded and on-screen wakes now leave the conversation and are listed Under the Hood, under "Switchboard & Medusa traffic", with every `tc message send` the pane shows. The chat header gains a Medusa indicator: the inbound and outbound heads blink when traffic moves, and the `@` badge becomes the unread count. It reads the listener status, which marks nothing read, never blinks for mail that was already waiting, and is hidden for a project that has not turned Medusa on.
- **"Waiting on you" lists every question** (#3079): it shows every question in the agent's newest reply, numbered when there are several. Each has a ✕ to dismiss it, and the list clears when you reply.
- **Long prompts** (#3079): a message longer than the 4,096 characters a session command takes is saved whole as a file in the project's secrets store (up to 5 MB, under a name no saved file already has, and only when that store can be checked). The session is sent as much of its start as fits, followed by the file's path. The conversation records the whole message when its record fits 8,000 bytes, and otherwise records the start and the file's path.

## Fixed

- **Message order and the message box** (#3079): your messages and the agent's replies now show in the order they happened, each once, instead of all your messages gathering above the replies. Pressing Enter clears the message box at once and shows the message at the bottom while it is sent; if the send fails, the text comes back.
- **A slimmer, easier-to-scan chat** (#3079): each message is tinted in its accent colour (blue for the operator, green for the agent) under a matching dashed divider. Active sessions, Health and Version move from the header to the footer status bar, and the chat header's member picker is hidden. While the Fleet Shell shows, the Classic admin controls sit in a "⋯ More" menu, with Classic View, Master and Advisor kept in the bar; Classic View puts every control back.
- **CI test job limit** (#3075, test in `test/ci-workflow.test.js`): the Tests workflow's job limit rises from 20 to 35 minutes. The suite, now about 30,900 tests, runs 16 to 20 minutes, so the old cap was cancelling healthy runs, including inside the release workflow. The job is still bounded.
