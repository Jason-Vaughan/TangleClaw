# v5.70.0 — Workspace migration and Orchestrator controls

Milestone #57 had zero open and four closed issues when this release candidate was cut. The dated [5.70.0] section of `CHANGELOG.md` compiles and consumes four accepted fragments.

- A guided workspace-root migration can plan moves from `~/Documents/Projects` to `~/Projects`, report active-session and target-path blockers, then update stored project paths and Git worktree links with rollback on failure (#2626).
- Projects configured with `repoFootprint: "hands-off"` receive an untracked `CLAUDE.local.md` operational guide. Their wrap records skip results for commit and PR creation, leaving the repository's tracked files alone (#1485).
- `tc capture <session-name> [--lines <N>]` provides an authorized, read-only view of a session's tmux pane. It limits output, redacts credentials, and audits permitted and denied attempts (#1774).
- Orchestrator is the canonical role name in new vocabulary and status metadata. Team Chat resolves `@orchestrator` and the compatibility aliases `@master` and `@project-master` through a server-verified roster identity. Existing internal Master identifiers remain for compatibility; their renaming is deferred to v6.0 (#2127).
