# v6.4.0 — A car gate matrix and train launch, consolidated train reports, a sprint setup gate, and fail-closed fleet isolation

TangleClaw v6.4.0 is a minor release on top of v6.3.0. The v6 workspace shows every car's gates at a glance and can activate a charter version and launch a train. Sprint reports can cover a whole multi-version train, a runtime gate checks the milestones, roadmap and report hub before a sprint is certified, and Medusa fleet isolation no longer fails open when a registry cannot be read.

## Added

- **Car progress matrix and gate board** (#3088; tests in `test/v6-b1-ui-shell.test.js` and `test/v6-fleet-wave-and-report-e2e.test.js`): the Sprint & Cars board gives each car a row, grouped by wave, with its lane, pull request, head commit and a pill for each of its six gates: Gate 0, A-Gate, O-Gate, PRR, CI and I-Gate. A gate the server records shows its status, commit and token. A gate only inferred from the car's stage is drawn as an outline, says "from stage" and never shows a commit; a closed car, which may have been cancelled, infers nothing past Gate 0. A gate nobody recorded says so, and one recorded against a different commit from the car's head is struck through.
- **Charter versions and train launch** (#3088): Charter & Roadmap now shows the open project's own charter, lists its versions with an Activate button on each one not yet active, and adds train launch controls. Paste the cars as a JSON list, then Compute waves, Check disjointness for shared files, or Start a wave run for a fleet. Each action sends the operator's proof and shows its result, or why it was refused. The server still refuses to activate a version whose approvals are incomplete.
- **Consolidated train reports** (#3089; tests in `test/v6-sprint-report-validator-v3.test.js` and `test/native-sprint-tracker.test.js`): Sprint Report Contract v3.1 adds an optional `fast_follow_subversions` list, so each small fast-follow release gets one remark row in its parent report instead of a full report or no record at all. A fast-follow marked as a major learning must link the Kaizen ledger item it produced and its postmortem entry, and the new validator Rule 11 refuses a report that leaves either out. `buildConsolidatedTrainReportSummary` totals pull requests, issues closed and token economics across a train's versions.
- **Sprint setup gate** (#3093): `verifySprintSetupAndRoadmapSync` holds certification when an open `vX.Y.Z` milestone has no release in the roadmap, an issue is placed more than once across the roadmap, the roadmap sync status is missing or not `ok`, or a sprint report directory is not linked from the Sprint Reports Hub. It reports as its own runtime guardrail (`setup_and_roadmap_sync`), so the post-mortem ledger's P0 to P11 rows are unchanged. The report validator also gains `validateHubReportLinks` and `ensureHubReportLinks`.

## Fixed

- **Fail-closed fleet isolation** (#3099; tests in `test/api-medusa.test.js`): a project in no group may still send to a workspace that no local project claims, such as a peer on another host. But while a registry of a project outside its fleet cannot be read, such a workspace may really belong to that project, so the send is now refused until the registry reads again; remote peers are refused during that window too. A broadcast's refusal says why (`details.reason: REGISTRY_UNREADABLE_OUTSIDE_FLEET`) without naming the other fleet, the server log lists every unreadable registry, and `allowCrossFleet: true` still sends.
