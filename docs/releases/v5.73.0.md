# v5.73.0 — Linux systemd companion stack, service reloads, and Medusa drift notifier

Milestone #60 had zero open and 7 closed issues when this release candidate was cut. The dated [5.73.0] section of `CHANGELOG.md` compiles and consumes 7 accepted fragments.

- Linux now has 1-to-1 background-daemon parity with macOS: `lib/linux-systemd.js` generates and verifies companion `systemd --user` units for ttyd, Caddy, and the Discord bridge helper alongside the existing server unit, and `deploy/install.sh` bootstraps a Linux host end-to-end (package manager detection, dependency install, ttyd build, systemd install) instead of requiring a manual setup (#2931, #2932).
- Runtime service reloads — a Caddy credential change, a ttyd rebind, a primary-checkout switch, and `scripts/ingress-cutover.js`'s full plan/apply/rollback — now run the equivalent `systemctl --user` command on Linux instead of only ever calling `launchctl` (#2933).
- The ttyd health detector now measures real Linux PTY exhaustion via `/proc/sys/kernel/pty/{nr,max}` instead of reporting "not applicable," and its remediation (along with `lib/master.js`'s own troubleshooting prose) correctly recommends the Linux companion unit's `systemctl` restart command rather than naming a macOS-only one — the detector reports the condition and the command; it does not run the restart itself (#2934).
- Fixed a launch-readiness status bug where a session that attested READY after its 2-minute unready-observation window had already fired kept reading as stuck ("needs-attention") forever (#2953).
- Check watch's wake/alarm messages now follow a literal one-wake contract: a send whose outcome was never learned is reconciled under the same idempotency key instead of opening a second exchange, asking the Medusa Hub's receipt-lookup endpoint first (#2347).
- Added a Medusa upstream/Hub drift notifier: a dashboard warning chip fires when the local `Medusa` checkout is behind `origin/main` or the running Hub is serving a stale `gitSha`, with a one-click Operator fix that fast-forwards the checkout and restarts the Hub, verified back to the new HEAD before reporting done (#2956).
