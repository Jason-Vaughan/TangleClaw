# v5.68.0 — Sprint tracking and continuity safeguards

Milestone #55 had zero open issues and five closed issues when this release candidate was cut. The dated [5.68.0] section of `CHANGELOG.md` compiles and consumes five accepted fragments.

- `lib/native-sprint-tracker.js` adds wave and file-disjoint car validation, dispatch-state tracking, sprint report and O-Gate summary models, and a roadmap sync helper with retry and an atomic last-good snapshot. `lib/routes/sprint-wave-routes.js#createSprintWaveRouter` and `public/sprint-wave-ui.js` are available adapters; they are not mounted in the live server or dashboard (#2644).
- `lib/coordinator-rotation.js#claimRelaunch` records which prepare-time Medusa messages remain owed across a relaunch. Resume cross-checks the successor inbox and explicit handled-message receipts against that snapshot (#2821).
- `lib/resource-lease-routes.js#handleAcquireLease` now calls `acquireLeaseWithPrimer` so callers of that handler attach the role's operating primer to acquired leases. The resource lease routes remain unmounted in the live server (#2888 feed-forward).
- The session drawer in `public/session.js` renders governed-wrap stream progress and offers a manual chunk-boundary lookup by assignment ID and chunk number. It does not infer those IDs from a session (#2735, #2736 feed-forward).
- Full-suite contention retries now reset state between real tmux TCC probes and Master Medusa HTTP test attempts (#2735, #2736). Feature Index graduation can proceed while a new `features-toc` append is staged (#748).
