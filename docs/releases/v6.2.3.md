# v6.2.3 — Chat replies as bubbles, chat attachments, inline session start and the Medusa-PM contract fallback

TangleClaw v6.2.3 is a fix release on top of v6.2.2. It makes the v6 Project Delegate Chat read like a conversation: the agent's replies appear as bubbles instead of staying inside a raw terminal dump, and files can be attached to a message. It also lets you start an offline session from the chat, adds status symbols to the sidebar, and finds Medusa's consumer contract on hosts where the Medusa checkout is registered as `Medusa-PM`. It adds no new routes or settings; the chat uses the existing secure-clipboard, session start, session status and model status routes.

## Fixed

- **Agent replies as conversation bubbles** (#3052, tests in `test/v6-b1-ui-shell.test.js`): replies are read from the session's live output for Claude Code, Codex, Antigravity and Aider, leaving out launch boilerplate, switchboard wake prompts, `tc` tool blocks, thinking and tool-run lines, and the engine's prompt and status chrome. They appear as `ASSISTANT (<project>)` bubbles after the recorded messages, escaped as plain text. A question the agent ends on stays pinned above the composer, and a one-line indicator shows when the engine is thinking or running a tool. The raw output sits in a collapsed "Under the Hood" drawer that remembers whether it is open, and both views open at their newest line and follow it while you are at the bottom. The bubbles are display only; the recorded conversation is unchanged.
- **Attachments in the chat composer** (#3053, tests in `test/v6-b1-ui-shell.test.js` and `test/v6-browser-shell-and-conversation-e2e.test.js`): drop files on the composer, paste them (screenshots included), or use 📎 Attach. Each file is uploaded into the project's secrets store through `POST /api/sessions/:project/secure-clipboard` and referenced in the sent message by the `.tangleclaw/secrets/` path the agent can open. A file over 5 MB, or one the server refuses, says why on its chip, and a message waits while a file is still uploading. A name already in the store gets a new name instead of overwriting it, and if the store's listing cannot be read, nothing is uploaded and each chip says why.
- **Start from the chat, and live status** (#3053): an offline chat offers `▶ Start` (a refused start shows the server's reason, with a link to Classic View for a start that needs its dialogs), and a project or fleet with offline members offers to start them all on a second click. An offline chat turns Active by itself once its session starts, and clicking any sidebar link, including the open one, refreshes session state. Each sidebar member shows its state (live, starting, wrapping, needs attention or offline), whether its Medusa link and wake are on, and its engine's health. A lane reached by clicking it directly is shown as the Designated Project Delegate when it is one, and the chat no longer repeats the Classic View link or shows the template and attestation pills.
- **Medusa-PM contract fallback** (#3053, tests in `test/sessions.test.js`): a session launched on a host where the Medusa checkout is registered as `Medusa-PM` now gets Medusa's consumer contract in its prime instead of "UNAVAILABLE". The checkout is looked up as `Medusa` first and then `Medusa-PM` (exact name, any case), and either is used only if it holds a non-blank contract, so a `Medusa` with no contract does not hide a real `Medusa-PM`. `MEDUSA_CONTRACT_PATH` still takes priority.
