# v6.2.1 — Full-stack soak, adversarial chaos and browser E2E qualification, and the dashboard startup fix

TangleClaw v6.2.1 is a qualification and fix release on top of v6.2.0. It fixes a dashboard startup error and an over-tight request limit on the report routes, and adds four test suites that exercise the real v6 modules, routes and release record end to end. It adds no new routes or settings.

## Fixed

- **Dashboard startup** (#3029): the dashboard no longer fails with `ReferenceError: renderCard is not defined`. Startup waits until every page script has run before installing the held-wake card badge, and a missing `renderCard` is skipped with a console warning instead of halting the page.
- **Report routes accept real reports** (#3041): `present`, `print-view` and `search-index` now accept up to 1 MiB, `cite` up to 2 MiB, and `ask` up to 8 MiB (the old 10 KB default refused every real report). Larger requests are still refused with 413.

## Qualification (internal)

- **Full-stack soak, chaos and master release qualification** (#3037): the real `lib/v6` modules under volume, sequential contention and injected faults on one SQLite store, plus checks across every v6 module, every `/api/v6` route and the release record.
- **Browser end-to-end suites** (#3038): shell, conversation, fleet, wave and report journeys through the real request handler and Fleet Shell.
- **Adversarial boundary suite** (#3039): 36 tests confirming each v6 trust boundary refuses input outside its contract.
- **Route-guard grammar** (#3044): every `/api/v6` handler must be an inline block that opens with a fail-closed caller check, with mutation regressions for each way it could be bypassed.
