# v6.5.8 — Critical runtime reliability, chat correctness & macOS APFS disk telemetry

TangleClaw v6.5.8 is a patch release on top of v6.5.7. macOS Full Disk Access no longer breaks across a Homebrew `node@22` upgrade, since the grant now targets a stable, staged binary path instead of the resolved Cellar path the `which node` symlink pointed at. V6 Chat no longer misreads an echoed or wrapped user prompt as an assistant reply, and a new centralized scroll coordinator keeps the chat stream and Under the Hood pinned to the newest line across drawer toggles, resizes, and async loads. `GET /api/system`'s disk usage now reports real APFS container fullness on macOS instead of the nearly-empty Sealed System Volume. Milestone [#102](https://github.com/Jason-Vaughan/TangleClaw/milestone/102): 4 of 4 issues closed.

## Fixed

- **macOS Full Disk Access survives a Homebrew node upgrade** (#3198): FDA was lost across a `node@22` upgrade because the grant was keyed to the resolved Cellar binary path, not the `which node` symlink `com.tangleclaw.server.plist` has always run — causing a stopped session under `~/Documents` to fail on relaunch. Adds `scripts/install-fda-anchor.sh --stage`, which stages the active, verified node binary (and its `libnode` dylib) at a stable path (`~/.tangleclaw/bin/node`) that survives every future patch upgrade, plus a non-destructive `--status` and an Operator-run `--cutover` that verifies a real FDA read of `~/Documents` before pointing the plist at the staged binary. `GET /api/system/health`'s FDA check now also reports the resolved node identity and the TCC-authorized tmux server's own health.
- **V6 Chat prompt-attribution dedup** (#3199): a terminal-echoed or wrapped user prompt no longer duplicates as a green ASSISTANT response — a queued-prompt preview row and its "send immediately" footer hint are no longer parsed as a reply, a multi-line or terminal-soft-wrapped prompt long enough to be cut off by the terminal's own column width stays part of the same user turn, and an optimistic send still in flight is no longer misread as a fresh assistant turn when a peek poll lands before the send settles.
- **Centralized chat scroll coordinator** (#3200, plus CSS/E2E coverage in #3220): toggling the Under the Hood drawer open or closed no longer jumps the chat stream or hides its newest message, and a ResizeObserver on the chat stream re-pins it to the bottom on any other container height change — a Gobble & Fill pane resizer drag, a window resize, or the docked header's own height changing — without misreading a shrink as the operator having scrolled away.
- **macOS APFS disk percent** (#3217): `GET /api/system`'s disk usage now reads `/System/Volumes/Data` (where user/application data actually lives) instead of the read-only Sealed System Volume at `/`, and corrects `used` to `total - free` when one volume's own `df` figure understates a shared APFS container's real usage. Previously a machine using ~75% of its disk read as ~2% full.
