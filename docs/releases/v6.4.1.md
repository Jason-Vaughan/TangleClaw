# v6.4.1 — A unified Waiting-On panel, composer polish, the native Release-First Roadmap, an onboarding wizard, mobile/foldable polish, and persistent macOS Full Disk Access

TangleClaw v6.4.1 is a minor release on top of v6.4.0. The v6 chat's "Waiting on you" slot becomes a unified 3-category panel, the composer and conversation stream resize against each other, and a refresh reliably jumps to the latest line. The 🧙 Wizard runs 3 real end-to-end workflows, and the shell gets a proper mobile slide-over drawer and foldable-width fixes. The v6 PM Workspace's Sprint & Cars, Kaizen & Reports and Charter & Roadmap tabs can now show the native Release-First Roadmap, 6-stage pills and reviewers through their existing live endpoints. A protected `~/Documents` tmux session routes unconditionally to the TCC-authorized server, the Antigravity CLI's survey prompt no longer wedges Medusa wake delivery, a large usage-transcript scan no longer overflows the call stack, the `gh pr merge` role guard recognizes multi-fleet lanes, a cross-fleet Medusa send explains an unreadable registry, and the roadmap publisher's `gh-pages` pushes no longer trigger Vercel failed-deploy emails.

## Added

- **Unified Waiting-On panel** (#3105; tests in `test/v6-b1-ui-shell.test.js`): "Waiting on you" is now a 3-category panel — **YOU** (CLI trust/permission/selector prompts and multi-choice questions detected in the live pane, merged with the existing direct-question list), **Your ToDo** (the operator's own handoff items extracted from the latest reply) and **AI** (queued follow-up prompts, Force/dismiss per item) — each numbered, dismissible, with a Clear button once it holds more than one item.
- **Interactive onboarding Wizard** (#3114; tests in `test/v6-b1-ui-shell.test.js`): the 🧙 Wizard tab now runs 3 real end-to-end workflows — create a standalone workspace project, convert an existing standalone project into a multi-seat fleet, or provision a new fleet from a template with a live plan preview — none of which clobber the active chat the way picking a template used to.
- **Native Release-First Roadmap, 6-stage pills and reports catalog** (#3112; tests in `test/native-sprint-tracker.test.js`): `lib/native-sprint-tracker.js#buildSprintWaveSnapshot` classifies each roadmap release as active, planned or shipped and maps every car's and issue's dispatch stage onto the canonical 6-stage pill (`Not started`, `In progress`, `In review`, `Blocked`, `Deployed, awaiting a check`, `Completed`). `public/sprint-wave-ui.js`'s existing `renderSprintWaveBoard` and `renderKaizenLedgerPanel` compose the new per-car execution cards and reports catalog automatically through their already-live `GET /api/sprint-waves` / `GET /api/sprint-reports/:version` endpoints — no route or shell change needed for those two tabs. `renderCharterReadinessPanel` composes the new roadmap panel the same way, given a `roadmapSnapshot`.

## Fixed

- **Composer polish and two-way resize** (#3106): an idle Waiting-on panel or activity line no longer charges a flex gap it never visually occupies; the attach control moved to a compact chip pinned over the message box's top-right corner; the message box and the conversation stream now resize against each other, down to a readable floor.
- **Scroll-to-latest and Usage Meter fallback** (#3113): a refresh (or a conversation still loading) now reliably jumps to the latest line instead of sometimes staying stuck mid-scroll; the Usage Meter falls back to a live session's own context-remaining reading when neither the pane nor a saved calibration has a weekly/5-hour percentage to show.
- **Mobile and foldable responsive polish** (#3117): the mobile `☰` menu is now a proper slide-over drawer with a backdrop and a styled toggle, instead of an unstyled full-width bar; the top bar no longer wraps into multiple left-aligned rows on Galaxy Fold and iPhone widths; the "Workspace Projects" sidebar entry no longer repeats itself as its own redundant child.
- **Persistent macOS Full Disk Access tmux routing** (#3108): a protected `~/Documents` tmux session now routes unconditionally to the TCC-authorized server, never the default server, even when the default server transiently passes a readability probe — macOS can revoke the default server's access 20–30 minutes later while the TCC-authorized server's own grant never lapses. The session's PATH-wrapper directory also stages `merge-role-guard.js` and `tmux-guard.js`, so the generated `gh`/`curl`/`tmux` wrappers never `require()` a path under `~/Documents` either.
- **Antigravity survey auto-skip** (#3111): the Antigravity CLI's inline feedback-survey prompt ("How's the CLI experience so far?") is now auto-dismissed with the Skip keystroke and a pane re-capture, so it no longer wedges Medusa wake delivery with `pane-no-prompt`.
- **Usage windows: no more parsed, and no more stack overflow** (#3092, #3109; tests in `test/usage-windows.test.js`): `tc usage windows` and the dashboard's Usage panel now say "No usage parsed from any local transcript log." when nothing was parsed, instead of never — every provider key is always present in the response. The v83→v84 usage-calibration migration now verifies its rebuilt table before committing. `GET /api/usage/windows` no longer throws `RangeError: Maximum call stack size exceeded` on a large transcript history, fixed at both places `lib/usage-windows.js` spread a scanned batch into a single `.push(...)` call.
- **Multi-fleet merge-role guard** (#3110; tests in `test/merge-role-guard.test.js`): the `gh pr merge` role guard now recognizes any `<fleet>-INT`/`<fleet>-Lane-INT` lane, `<fleet>-PRR`/`<fleet>-Obsr`, `<fleet>-Arc`, `<fleet>-PM` and `<fleet>-Lane-<letter>`, plus `TiLT v2` (the real stored project name, with a space) and `Monad-1` by name, and lets `Monad-1` merge with `--squash` while every other fleet, including `TC-Lane-INT`, stays restricted to `--merge`. A new `allowedMergeMethods` option generalizes the same per-caller exception for any other repo's own convention.
- **Medusa cross-fleet registry-unreadable diagnostic** (#3103): a Medusa send to an unmapped workspace now says why when it's refused because a project registry outside the sender's fleet could not be read, instead of a bare "not in your fleet" — matching the wording the same case already got for broadcasts.
- **Vercel gh-pages deploy-email guard** (#3116): the roadmap publisher's `gh-pages` pushes no longer trigger Vercel's "Root Directory 'website' does not exist" failed-deploy emails — `lib/roadmap-vercel-guard.js` stages a deterministic skip-build `vercel.json` into a `gh-pages` checkout and marks its commits `[skip ci] [vercel skip]`.

## Status corrections and follow-ups

- [#3112](https://github.com/Jason-Vaughan/TangleClaw/issues/3112)'s Charter & Roadmap tab: Sprint & Cars and Kaizen & Reports already show the Release-First Roadmap live, through their existing `GET /api/sprint-waves`/`GET /api/sprint-reports/:version` passthrough pipes. Charter & Roadmap needed a third piece — PR #3122 (Car V641-W2-A) added it, passing a `roadmapSnapshot` into `renderCharterReadinessPanel` from `public/v6-shell.js` — but `GET /api/sprint-waves`'s response has no `snapshot` field yet, so that passthrough is a forward-compatible no-op (`roadmapSnapshot` resolves to `null`) until `lib/routes/sprint-wave-routes.js` is wired to call `buildSprintWaveSnapshot` and include it. That route-layer piece is still open.
