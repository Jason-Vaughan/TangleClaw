# v5.71.0 — OpenClaw connection resilience and visibility

Milestone #58 had zero open and six closed issues when this release candidate was cut. The dated [5.71.0] section of `CHANGELOG.md` compiles and consumes six accepted fragments.

- OpenClaw connections can use ordered fallback SSH hosts. The resolver picks the highest-priority reachable address, exposes the active route, and reprobes after an SSH failure. An IP-literal audit and operator-confirmed MagicDNS migration retain the former IP as a fallback by default (#1531, #363).
- The OpenClaw landing page can show an update-available badge when comparable image tags are available. An optional validated `.env` tag-update helper is exposed through the connection API (#297).
- The connection dot is rechecked on the existing sidecar poll cycle and ages stale gateway measurements out of `live` after two minutes. Resource and health detection plus a header-pill renderer are included; a later route must supply live telemetry to those pills (#1185, #128).
- Direct OpenClaw proxy requests strip stale Cloudflare attribution headers before forwarding. Direct Control UI pages also receive a stable browser identity bridge and invoke TangleClaw's existing device-approval route; whether an OpenClaw bundle reads the bridge itself depends on that bundle (#254).
