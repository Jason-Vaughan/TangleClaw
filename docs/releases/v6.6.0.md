# v6.6.0 — Fleet Pack schema v1.1, control-plane merge broker verification, ephemeral launch-secret scrubbing, and website dependency/deploy hygiene

TangleClaw v6.6.0 is a minor release on top of v6.5.12, shipping Sprint v6.6.0 Wave 1's Phase 1
Immediate Hardening work. The canonical Fleet Pack schema gains `schemaVersion: "1.1"` alongside
the existing `"1.0"`, with four portability guardrails — symbolic `seatId` addressing, logical
`${FLEET_SHARED_DIR}`/`${SEAT_WORKSPACE_DIR}` path-token substitution on export, an explicit
enumerated `authorityClass` per seat, and a hard separation between a Plane A blueprint and Plane
B instance-binding data — plus a new `exportFleetPackBlueprint` Plane A dry-run exporter. The v6
Control-Plane GitHub Merge Broker gains mechanical 4-gate verification, checking `O-Gate`/
`A-Gate`/`R-Gate`/CI `PASS` receipts pinned to the exact head sha and forbidding direct merge
execution by any actor authority other than `integrator`/`operator`. `lib/tmux.js` gains
`scrubSessionLaunchSecrets`, wired automatically into session creation: an ephemeral launch
secret handed to a session no longer lingers in its tmux environment table, where a peer session
under the same UID could otherwise read it back via `tmux show-environment`. Separately, the
unused Homebrew `openjdk` bin directory is stripped from the server LaunchAgent's `PATH`
template, `website/` dependencies are bumped to close 8 Dependabot alerts, and the canonical
security posture & credential-isolation assessment is now tracked in-repo. Milestone
[#94](https://github.com/Jason-Vaughan/TangleClaw/milestone/94): 3 of 3 issues closed.

## Added

- **Fleet Pack schema `"1.1"` & portability guardrails `PG-1`–`PG-4`** (#3194, Ruling A1042):
  `lib/v6/fleet-template-spec.js` adds the canonical `schemaVersion: "1.1"` alongside the
  existing `"1.0"` — `PG-1` requires a `"1.1"` seat's `seatId` to be symbolic, rejecting a raw
  numeric SQLite `project_id` or a runtime Medusa workspace suffix; `PG-2` substitutes logical
  `${FLEET_SHARED_DIR}`/`${SEAT_WORKSPACE_DIR}` path tokens and strips `~`-relative host paths on
  export; `PG-3` requires an explicit, enumerated `authorityClass` per seat; `PG-4` forbids a
  Plane A blueprint from carrying Plane B instance-binding data. Adds the new
  `exportFleetPackBlueprint` Plane A dry-run exporter and `validateInstanceBindingRecord` Plane B
  counterpart. `"1.0"` specs, including both existing `BUNDLED_FLEET_SPECS` entries, validate
  exactly as before — every guardrail is additive to `"1.1"` only.
- **Control-Plane GitHub Merge Broker 4-gate verification** (#3212 Phase 1.1): `lib/v6/c3-merge-queue.js#verifyFourGateMergeReadiness`
  mechanically checks `O-Gate`/`A-Gate`/`R-Gate`/CI `PASS` receipts pinned to the exact head sha,
  and `authorizeControlPlaneMerge` additionally forbids direct merge execution by any actor
  authority other than `integrator`/`operator`.
- **Ephemeral launch-secret scrubbing** (#3212 Phase 1.2): `lib/tmux.js#scrubSessionLaunchSecrets`,
  wired into `createSession` and `createSessionWithTccBootstrap`, automatically removes ephemeral
  launch-secret environment variables (`TANGLECLAW_LAUNCH_SECRET` by default) from a session's
  tmux environment table right after bootstrap, on the default server and the TCC-authorized
  server's real session alike — gated so an ordinary launch that never carries one of these keys
  costs nothing extra.

## Fixed

- **Website dependency floor & deploy `PATH` hygiene** (#3211, #3212 Phase 1.2): stripped the
  unused Homebrew `openjdk` bin directory from the server LaunchAgent's `PATH` template, and
  bumped `website/` dependencies (`next` to `16.4.6`, `minimatch` to `11.0.9` for the
  `@typescript-eslint/typescript-estree` toolchain only) to close Dependabot alerts #21–#28. The
  canonical security posture & credential-isolation assessment is now tracked at
  `docs/security/tangleclaw-security-posture-and-credential-isolation-assessment.md`.
