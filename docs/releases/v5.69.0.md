# v5.69.0 — Medusa coordination and session recovery

Milestone #56 had zero open issues and five closed issues when this release candidate was cut. The dated [5.69.0] section of `CHANGELOG.md` compiles and consumes five accepted fragments.

- An operator or a coordinator can send one explicit Medusa broadcast to other active registered switchboards. `lib/medusa.js#broadcastAll` marks it `[BROADCAST scope=all]`, applies a per-sender cooldown, and coalesces an identical retry within that window (#1224).
- The Master control bar and project session banner use the shared `tcCreateMedusaLoops` component for loop setup, status, feedback, closeout, and transcript controls. The Master launch affordance remains hidden at its read-only access level (#1083).
- The inbox compose row accepts `@nickname` tags, resolves them against the live roster, and sends to matching peers; unmatched or missing tags refuse before sending (#1576).
- Once a session's launch is READY and its Medusa listener is active, the launch path can announce it to other projects' active architect or project-manager coordinators. Project config and an environment flag can disable these startup announcements (#1732).
- A verified coordinator session from another project can clear a stalled peer launch through `POST /api/sessions/:project/launch/recovery-clear-peer`. The clearance records the coordinator session, project, role, launch, and reason separately from the target project in schema v79 (#1713).
