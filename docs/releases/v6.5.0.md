# v6.5.0 — Rich link unfurling and inline media previews, a Portable Fleet Template JSON Spec, and an Update button that backs up local changes

TangleClaw v6.5.0 is a minor release on top of v6.4.1. v6 chat renders rich link previews and inline media/artifact cards instead of bare URLs, and a whole fleet can now be exported as a portable `.fleet.json` spec and re-provisioned elsewhere through a 4th Wizard tab. The dashboard's Update button no longer dead-ends on a checkout with local real-work changes. The Release-First Roadmap also goes fully live across all three v6 PM Workspace tabs — the one piece v6.4.1's release notes flagged as still open.

## Added

- **Rich link unfurling and inline media/artifact previews** (#3107; tests in `test/v6-b2-conversation-layer.test.js` and `test/v6-b1-ui-shell.test.js`): `lib/v6/b2-conversation-layer.js` gains the classification/parsing core — local image/video/artifact (including `#L<n>-L<n>` code line-range) card models, GitHub PR/Issue/Release URL parsing, Open Graph HTML parsing, and an SSRF guard for external unfurl targets. v6 chat renders it: a GitHub PR/Issue/Release URL becomes a structured chip, any other external link gets a click-to-reveal preview (title/description, never auto-fetched) backed by a new SSRF-guarded unfurl endpoint, and a `file://` URL or workspace-rooted path renders as a metadata/artifact card with no byte-fetching and no new local-file-serving route.
- **Portable Fleet Template JSON Spec** (#3115; tests in `test/v6-c2-fleet-templates.test.js`): `lib/v6/fleet-template-spec.js` adds a `.fleet.json` (`schemaVersion` `"1.0"`) validator (`validateFleetSpec`), a sanitized export engine (`exportFleetSpec`, stripping local filesystem paths, secrets and session tokens), a dry-run import preview (`previewFleetSpecImport`), and a provisioning-plan builder (`applyFleetSpecImport`), plus two bundled flagship reference specs — `software-factory-10-role` and `ai-design-agency` — and `tangleclaw.com` ecosystem directory metadata. The v6 Wizard gains a 4th "Fleet Spec" tab: browse the bundled reference templates and the marketplace, paste/validate/import a spec to provision a real fleet, or export an existing workspace as a portable spec, backed by new `GET /api/v6/fleet-templates/bundled-specs`, `GET /api/v6/projects/:id/fleet-spec`, `POST /api/v6/fleet-templates/validate-spec` and `POST /api/v6/fleet-templates/apply-spec` routes.

## Fixed

- **The dashboard Update button backs up local changes instead of refusing** (#3126): a checkout with local real-work changes no longer dead-ends the Update button; confirming now backs up each conflicting file to `~/.tangleclaw/backups/` and restores or removes it so the update can proceed. A delegated coordinator's governed `/clear` no longer carries a sender stamp, which would otherwise be typed as part of the slash command.

## Status corrections and follow-ups

- [#3112](https://github.com/Jason-Vaughan/TangleClaw/issues/3112) is now fully resolved. v6.4.1's release notes flagged that `GET /api/sprint-waves` had no `snapshot` field, so `public/v6-shell.js`'s `roadmapSnapshot` passthrough (added in PR #3122) was a documented no-op. `lib/routes/sprint-wave-routes.js` now calls `buildSprintWaveSnapshot` and returns it as `snapshot`, so the Release-First Roadmap renders live in `📜 Charter & Roadmap` alongside `🚂 Sprint & Cars` and `📈 Kaizen & Reports`.
