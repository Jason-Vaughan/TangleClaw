# v6.5.12 — Mechanical fleet parallelization, non-blocking async session launch, engine state convergence, and Medusa wake fixes

TangleClaw v6.5.12 is a minor release on top of v6.5.11. The Wave Scheduler gets a Mechanical Maximum Fleet Parallelization Guard that mechanically shards issues into file-disjoint parallel waves instead of letting a plan collapse into single-stream drift. Session launches can now run non-blocking: `POST /api/sessions/:project?async=true` returns an accepted "starting" receipt immediately and defers the real launch (including slow tmux probes and session-history scans) off the request path, with a single-flight claim held through the full launch so a concurrent launch for the same project is refused instead of racing it. `tc model switch` no longer misclassifies a cross-provider switch when the stored engine id has drifted from the actually-running session, and `project.json`'s own `engine` field now stays in sync alongside `model`. A governed session wrap's learnings-capture gate no longer wedges under macOS TCC restrictions on `~/Documents`, falling back to the TCC-exempt managed workspace mirror. The Medusa wake monitor no longer permanently misreads a session as mid-turn after it merely quotes its own busy/idle marker phrases in prose, and a stray tmux copy-mode overlay on a TCC-bootstrapped session's real pane is now cleared alongside the thin attach-proxy. Milestone [#106](https://github.com/Jason-Vaughan/TangleClaw/milestone/106): 3 of 3 issues closed.

## Added

- **Mechanical Maximum Fleet Parallelization Guard** (#3213): `lib/v6/c3-wave-scheduler.js#planParallelWaveShards` mechanically shards a flat list of issues into file-disjoint, lane-capacity-bounded parallel waves — one Car per available Builder lane, `dependsOn` set only when an issue is pushed past Wave 1 by a real file-scope conflict or every lane being taken. `validateParallelWavePlan` rejects a plan that collapses multiple issues into a single Wave 1 Car (single-stream drift) unless an explicit `serialReason` is attested or every later Car genuinely, pairwise conflicts with Wave 1's one Car. `WaveScheduler#createRun` enforces the guard inline when `metadata.enforceParallelSharding` is set, before persisting anything; existing callers that never set it keep prior behavior exactly.
- **Non-blocking async session launch** (#3216 Pillar 2): `launchSessionAsync` in `lib/sessions.js` returns an accepted `"starting"` receipt immediately after its synchronous admission checks, deferring the real launch to `setImmediate` so a slow tmux probe or spawn never blocks the request. `POST /api/sessions/:project` supports `?async=true` / `body.async === true`, reusing the synchronous path's existing error classification unchanged when omitted. A single-flight claim holds through the full launch, including a WebUI continuation's own promise, so a concurrent launch request for the same project is refused `409 ALREADY_STARTING` rather than racing it. For a model-override launch, `lib/profile-reconciler.js#snapshotExistingSessionIdsAsync` scans the engine's session-history files for prior session ids, yielding to the event loop every 20 files so a scan that can take several seconds on a machine with heavy session history no longer blocks the process solid while it runs.

## Fixed

- **Engine state convergence on model switch** (#3216 Pillar 3): `tc model switch` no longer misclassifies a cross-provider switch as a same-provider live reconcile when SQLite's `projects.engine_id` has drifted from the actually-running session's own engine — `sameProvider` is now decided from the live session's `engineId`, falling back to `projects.engine_id` only when a session is absent. `project.json`'s own `engine` field is now kept in sync alongside `model` too, so a `project.json` that already names an `engine` never goes stale.
- **TCC-safe managed workspace fallback for learnings-capture** (#3216 Pillar 4): macOS TCC permission restrictions on `~/Documents` could wedge a governed session wrap's `learnings-capture` gate and its DB mirroring when a project's `.tangleclaw/memories/learnings.md` is EPERM/EACCES at its primary path — both steps now also check the TCC-exempt managed workspace mirror, judging whichever of the two readable candidates is fresher, with a best-effort mirror sync back to the primary path once it becomes writable again.
- **Medusa wake status-chrome scoping & stray copy-mode overlay** (#3247): the wake monitor no longer permanently reads a Claude or Antigravity session as mid-turn after a reply merely quoted the engine's own busy/idle marker phrases ("esc to interrupt", "esc to cancel", "? for shortcuts") in prose — `_assessActivity` now scans only the pane's trailing status/composer chrome for these markers, not the whole captured transcript. Also fixed a wake nudge never clearing a stray tmux copy-mode overlay on a TCC-bootstrapped session's real inner socket — only the thin attach-proxy on the default socket was ever cleared before; `_cancelStrayCopyMode` now clears both.
