# v6.5.10 — Sub-100ms V6 navigation caching, animated ellipsis loading indicators, and Engine Usage pop-up fixes & card layout

TangleClaw v6.5.10 is a minor release on top of v6.5.9. Clicking a fleet member, fleet, or workspace tab in V6 Shell now updates the active selection and shows the target route's own loading state immediately from whatever is already cached, instead of blocking on a fresh sequential reload of projects, engine health and fleet templates on every click — that refresh, and a live chat's status/output-peek/Medusa-listener reads, now run in the background instead of serially. Every static "Loading…" text across V6 Shell gained a shared, accessibly-animated ellipsis indicator with context-specific labels and full `prefers-reduced-motion` support. The Engine Usage pop-up's `↻ Refresh now` button and auto-refresh interval control now actually work — both requests were silently missing a required header and were refused outright every time — and a provider probe that fails on one refresh no longer loses its last-known-good reading; the pop-up itself now groups each engine's quota into one clearly labelled card instead of two separate, unlabelled blocks. Milestone [#104](https://github.com/Jason-Vaughan/TangleClaw/milestone/104): 4 of 4 issues closed.

## Added

- **Sub-100ms V6 navigation caching & parallelized chat bootstrap** (#3206): clicking a fleet member, fleet, or workspace tab now updates the active selection and shows the target route's own loading state immediately, from whatever is already cached, instead of blocking on a fresh sequential reload of projects, engine health and fleet templates on every click — that refresh now runs in the background. Opening a live chat also fires its status, output peek and Medusa-listener reads together rather than one after another, and its conversation history and attestations now start loading the moment the session status is known, rather than waiting on that output peek and listener read to finish first too.
- **Animated ellipsis loading indicators** (#3207): every static "Loading…" text in V6 Shell (chat/settings detail pane, chat history panel, fleet plan/template loading, the usage probe's own refresh/interval status line) now shows a context-specific, accessibly-animated ellipsis indicator — "Loading chat…", "Retrieving history…", "Refreshing usage probe…", and so on. A new shared helper in `public/api-helper.js`, `tcV6AnimatedEllipsisMarkup(label)`, renders the static markup for any context-specific label, normalizing any trailing dots so it's never doubled up with the animated ones; `tcV6CreateAnimatedEllipsisController(opts)` mounts a live version that cycles `.` → `..` → `...` → `.` on an interval, skips the animation entirely (a static `...`) under `prefers-reduced-motion: reduce`, and can update its own label, stop cleanly, or fail into an actionable error message with an optional Retry button — one implementation reused everywhere a page previously rolled its own wait state.
- **Structured per-engine Usage pop-up cards** (#3209): the Engine Usage pop-up now groups each engine's provider-reported quota and locally-estimated usage into one clearly labelled card per engine (Claude, Codex, Antigravity), instead of two separate, unlabelled blocks — the refresh/interval controls stay pinned once at the top rather than repeating per engine. A new `tcV6RenderEngineUsageCardMarkup` helper renders one card per provider with a source badge ("Provider Probed" vs "Local Estimate"), aligned 5-Hour and Weekly quota window rows (a progress bar, a "% left" badge, and a readable reset countdown via the new `tcV6FormatResetCountdown`), a sub-tier breakdown (Claude's Fable, Antigravity's Claude & GPT models) when the probe reports any, this host's own Local Transcript Token & Session Aggregates kept visually separate from the provider-probed percentages, and a degraded-refresh note that surfaces a probe failure without hiding the last known-good quota bars.

## Fixed

- **Engine Usage refresh/interval requests & partial-failure preservation** (#3208): clicking `↻ Refresh now` or changing the auto-refresh interval in the Engine Usage pop-up now actually works — both requests were silently missing a required `Content-Type: application/json` header and the server refused them outright every time. Separately, a provider probe (`claude`/`codex`/`antigravity`) that finds nothing on a transient refresh failure no longer loses its previous valid reading: it now preserves the prior percentages, resets, and sub-tiers, marking it `refreshDegraded: true` with `lastRefreshError` naming why, rather than overwriting it with nulls — the pop-up shows the provider's own error note and last-probed timestamp instead of a bare status badge. A successful refresh now also records `lastSuccessObservedAt`, and `refreshAllUsageProbes` uses `Promise.allSettled` so one provider's unexpected failure can no longer take the other providers' already-successful readings down with it.
