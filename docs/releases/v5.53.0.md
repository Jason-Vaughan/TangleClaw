# v5.53.0 — Master authority and continuity

This release gives the Project Master a bounded lifecycle authority, reports continuity health, and closes session mutation paths that accepted the wrong caller. The [release status](v5.53.0-status.md) tracks code publication, the local server update, and live activation separately.

- A verified Operator can set the Master's lifecycle access level. Only `write` grants fleet lifecycle actions; the Master's own calls require its scoped API token, current authority generation, and an allowed action. Both authority write paths require Operator proof and reject launch-binding headers.
- Session launch and kill admit only a verified Operator or authorized Master. A project session may wrap only its own current session.
- Master status can report continuity health from a supplied context or pane-buffer reading. Without one, it reports `unmeasured`; it does not relaunch the Master.
- Imported and attached projects receive the ratified PM/Architect onboarding trust rule as a proposal for Operator review. Project listings expose operator-owned setting discrepancies while recovery mode keeps its existing DB-backed pin.
- An opt-in machine-client setting can require an AUTH-4 token from loopback callers. It is off by default and has no settings UI yet.

The release notes in `CHANGELOG.md` cover all seven Charter A491 issues: #2120, #2125, #1982, #1973, #2132, #966, and #2129.
