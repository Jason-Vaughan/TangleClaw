## Why 5.35.0

The section holds `### Added`, `### Changed`, `### Fixed` and `### Internal` entries and no `BREAKING` marker, which this repository's bump table reads as a minor release: 5.34.0 to 5.35.0.

## What it contains

`CHANGELOG.md`, section `[5.35.0]`, is the list: 24 top-level entries, 2 Added, 3 Changed, 2 Fixed and 17 Internal. It is the first section compiled from changelog fragments: the release pull request compiled the 24 files under `changelog.d/` into `[Unreleased]` with `lib/changelog-fragments.js`, promoted that to `[5.35.0]`, and deleted the fragments, as a wrap's release cut does. It publishes 13,588 bytes of release notes against the release gate's ceiling of 120,000 (`node lib/changelog-notes.js 5.35.0`, measured by `node scripts/release-notes-gate.js`).

The milestone "v5.35.0: Cheaper parallel work" holds six issues: three closed (#2498, #2042, #1903) and three open (#1220, #2248, #2015; below). #2042 and #1903 were closed during v5.34.0 and shipped in it.

The release ran as five waves on a single Builder lane. In summary, by wave; the entries themselves are the authority:

- **Wave 1 (#2015).** The `docs/releases/v5.34-status.md` post-publication sync (#2517). #2015's preference work is parked, so nothing of it ships.
- **Wave 2 (#1220).** Per-change changelog fragments under `changelog.d/`: the fragment contract, the wrap asking for a fragment, the release cut compiling them, and the suite checking every fragment (#2518, #2520, #2522, #2526), proved by a two-pull-request pilot (#2524, #2525). A pull request that only logs its work no longer conflicts with another's. The wrap's feature index no longer offers to stub a fragment as a source file (#2519).
- **Wave 3 (#2248, part one).** `server.js` and `lib/store.js` split by area, one extraction per pull request (#2528 to #2530 and #2532 to #2539), with `docs/areas.json` mapping every source area. Every move is unchanged code; the store's schema and its migration chain moved intact.
- **Wave 4 (#2498).** The five-stage test pyramid: a tier for every test file (`test/tiers.json`), one entry point per stage (`scripts/test-stage.js`), Stage 2's touched-file selection, two report-only redundancy audits, the `.testament.toml` manifest, and `scripts/suite-evidence.js`, the CI-as-suite-evidence command for #2371, built and declared nowhere (#2541, #2542, #2543, #2545, #2550, #2551).
- **Records.** Each wave closed with a records pull request (#2527, #2540, #2552).

The store stays at schema 68. `CURRENT_SCHEMA_VERSION` is 68 at the `v5.34.0` tag (`lib/store.js`) and at `1e608f28` (`lib/store/_schema.js`), and the migration chain names the same 26 `_migrate*` functions at both. No migration was added or changed, so no upgrade rehearsal was run for this release.
