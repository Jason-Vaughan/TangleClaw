# v6.2.2 — Fleet View sidebar, Project Delegate Chat and the Medusa update chip fix

TangleClaw v6.2.2 is a fix release on top of v6.2.1. It makes the v6 Fleet View usable as a working surface: the sidebar no longer pushes the main pane off screen, and clicking a project opens a chat with that project's delegate instead of a read-only event list. It also fixes the Medusa update chip, which could do nothing at all when clicked. It adds no new routes or settings; the chat sends through the existing `POST /api/sessions/:project/command` route.

## Fixed

- **Fleet View layout and sidebar** (#3046, tests in `test/v6-b1-ui-shell.test.js`): the main pane sits beside the sidebar instead of below it, and the sidebar scrolls on its own and keeps its place. The sidebar can be hidden (`« Hide Fleet` / `» Show Fleet`), each project and fleet folds (with Expand all / Collapse all), and it filters by text, engine and one or many project pills (Multi, or Ctrl/Cmd/Shift-click; All resets). These choices are remembered. The Classic/Fleet switcher moved into the page header, and the Classic filter toolbar hides while the Fleet View shows.
- **Project Delegate Chat** (#3047, tests in `test/v6-b1-ui-shell.test.js` and `test/v6-browser-shell-and-conversation-e2e.test.js`): clicking a project or fleet opens a chat with its Designated Delegate: the `-PM` member by default, then `-Master`, then the first member with a live session. The delegate can be changed from the chat header. The chat shows the session's status, the recorded conversation and its live output (refreshed every 4 seconds). A sent message is typed into the session and recorded in the conversation, even if you move to another chat before it lands. A refusal (a held lane, a session that is not ready, a running wrap) shows the server's reason and keeps the text.
- **Medusa update chip** (#3048, tests in `test/medusa-drift.test.js` and `test/update-beacon.test.js`): the chip used the browser's `confirm()`, which some browsers and webviews suppress, so a click could do nothing. It now confirms on the chip itself (a second click within 10 seconds). A refusal or failure stays on the chip with its reason. The update no longer refuses over untracked files or `.tangleclaw/` runtime state, and a refusal names the changed files and the branch. On macOS, a Hub restart is refused, with the running Hub left alone, when the `com.medusa.hub` LaunchAgent's `WorkingDirectory` is missing or its plist cannot be read.
