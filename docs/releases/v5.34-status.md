## Why 5.34.0

The section holds `### Added`, `### Changed`, `### Security`, `### Fixed` and `### Internal` entries and no `BREAKING` marker, which this repository's bump table reads as a minor release: 5.33.1 to 5.34.0.

## What it contains

`CHANGELOG.md`, section `[5.34.0]`, is the list: 87 top-level entries, 8 Added, 8 Changed, 1 Security, 27 Fixed and 43 Internal. It publishes 21,032 bytes of release notes against the release gate's ceiling of 120,000 (`node lib/changelog-notes.js 5.34.0`, measured by `node scripts/release-notes-gate.js`).

The milestone "v5.34.0: A suite you can trust" holds 67 closed issues and 1 closed pull request, and four open items (below).

In summary, by subsection; the entries themselves are the authority:

- **Added.** The host check, `node scripts/host-check.js`, and a guide to moving TangleClaw to another machine (#1380, #2142). The merge queue will not land while its owner has an unhandled message (#2372), and the Operator can settle an entry stuck in `landing` (#2364). Shared documents keep a record of every observed revision, with attested authorship (#2389). Turning a launch-isolation override on asks first, and the dashboard says while one is on (#2393). The landing page says so when no login is in force (#2378). Wrap activity records the paths answered Include and Leave (#2155).
- **Changed.** Soak runs sign in as an Operator account and run their switchboard cycles as their sessions (#2240). Shared-document change notices go only to the owners of the rows changed and to subscribers (#2389). A refused launch's message stays until it is dismissed (#2339). With no login in force, operator routes that grant or approve authority refuse until the operator signs in (#2378). The stranded-config scan flags `GEMINI.md` (#1049); the wake waits one more settling interval after a busy Codex turn; the wrap drawer names who merges a coordinator's wrap PR (#2366).
- **Security.** A member session can take a shared-document lock only under its own verified session and project name (#2489).
- **Fixed.** Codex 0.161.0 and 0.162.0 stay refused, now on a measurement (#2222). A Medusa listener that reconnects after a Hub outage keeps its connection (#2370). Release-certification checks no longer trip over their scratch repository (#2088). Only a lock's holder or the Operator can release a shared-document lock (#2290). Launch blockers can no longer stall a launch, a status poll or the card (#2204, #2194, #2196, #2201, #2206, #2450). The host check prints no raw values or unknown error codes. Project Settings no longer scrolls sideways on a narrow phone (#2361). And the other entries listed there.
- **Internal.** Test-helper consolidation (#1903, chunks 01 to 10; Chunk 10 closes #1903), load-proofing of timing tests (#2200, #2184, #2481, #2447, #2152, #2485, #2504), the CI-as-suite packet, not in force (#2371), and documentation.

The store moves from schema 66 (v5.33.1) to schema 68. Each step adds tables and changes no existing one: v67 adds `shared_doc_events` and `shared_doc_baselines`, v68 adds `shared_doc_notice_prefs` and `shared_doc_deliveries` (#2389). Both migrations are a `CREATE TABLE` and a postcondition check (`_migrateSharedDocEventsV67`, `_migrateSharedDocNoticesV68` in `lib/store.js`), with no `ALTER`, `DROP`, `UPDATE` or `DELETE`. An older TangleClaw opens the upgraded store and ignores the new tables.

## After the upgrade, the operator must

- **Know that an install with no login refuses its authority-granting operator routes** (#2378): session-rule approval, global and Master rules, learning tiers, coordinator grants, releasing a HOLD, merge-queue creation and gates, shared-document registration, group membership, recovery mode and the startup prompt answer `403 LOGIN_GATE_REQUIRED` until a login is in force and the operator is signed in. The landing page shows a notice with an **Add a login** button while none is. An install with a login in force is unaffected.
- **Nothing else** is required by the `CHANGELOG.md` entries. Codex 0.161.0 and 0.162.0 remain refused, as in v5.33.1.

## Upgrade rehearsal

Run on 2026-10-19 from 19:16:44 to 19:16:46 UTC, in isolation, at commit `9448c963` (the code this release tags; the release pull request changes no code), by TC-Lane-B, by the method the Architect accepted for this release.

The live store was copied with `sqlite3 .backup` into a private scratch directory under the session's own scratchpad, and the copy opened by that commit's own `lib/store.js` (`init()`, then `close()`) with its base path and `TANGLECLAW_HOME` set to that directory. No server was started on the copy. The live server, its database and its log were not touched beyond the backup's read. The scratch directory was deleted afterwards and confirmed gone.

| Store copied | Schema before | Schema after | Integrity | Foreign-key violations | Bridge schema problems | Tables lost | Row counts changed |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| The live store, copied at the rehearsal (73 tables, 403,558 rows) | 66 | 68 | ok | 0 | none | none | only `schema_version` (one row added) |

Four tables were added, each empty: `shared_doc_events`, `shared_doc_baselines`, `shared_doc_notice_prefs` and `shared_doc_deliveries`. Opening the upgraded copy a second time changed nothing: schema, tables, every row count, integrity and foreign keys read the same. Only counts and verdicts were recorded, never row contents.

**Why no server was started on a copy.** A TangleClaw server started on a copy of the live store would read the live sessions from it, connect to the switchboard under their identities and run its monitors against the real tmux panes of this host.
