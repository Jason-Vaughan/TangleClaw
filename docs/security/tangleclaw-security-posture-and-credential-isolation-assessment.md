## 1. Executive Summary

This assessment evaluates TangleClaw's empirical security posture across six domains mandated by the Operator Directive and Fast-Follow Addendum 01 (`2026-11-22`):

1. **Java Runtime / Java4Shell (`CVE-2026-114938`, disclosed Nov 17, 2026):** **`NOT AFFECTED` (`0` active exposure).** Although Homebrew `openjdk 25` (`2025-09-16`) exists on disk at `/opt/homebrew/opt/openjdk/bin/java` and was listed in `com.tangleclaw.server.plist`'s `PATH`, TangleClaw (`server.js`, `lib/**`, `bin/tc`, `ttyd`, `tmux`, Medusa, and all 4 GitHub Actions workflows) runs **zero** Java processes, JVM services, or JNDI/serialization endpoints (`ps aux | grep -i java` -> `0` processes).
2. **Node.js Runtime (`v22.22.3` vs. Nov 11, 2026 Security Releases & `BUG-002` / `#3198`):** **`CONFIRMED MAINTENANCE GAP (Medium)`.** The host runs `/opt/homebrew/Cellar/node@22/22.22.3/bin/node` (built May 2026). External network exposure is mitigated because `server.js` binds loopback (`127.0.0.1:3102`) behind Caddy TLS on Tailscale MagicDNS (`:8443`) and `AUTH-2` (`lib/auth-gate.js`). Upgrading Homebrew `node@22` must be coordinated with `#3198` (`BUG-002` in `v6.5.8`) so the staged TCC-authorized `~/.tangleclaw/bin/node` binary and `com.tangleclaw.bridge-helper.plist` are updated atomically without losing macOS Full Disk Access.
3. **npm & Software Supply-Chain Security (`8` Open Dependabot Alerts `#21`–`#28`):** **`CORE CONTROL PLANE IMMUNE; WEBSITE DEPENDENCIES ACTIONABLE (Low/Medium)`.** TangleClaw's root control plane has **no root `package.json` or `node_modules`** — it executes 100% on Node.js 22 standard library built-ins (`node:http`, `node:sqlite`, `node:crypto`, `node:fs`). All `8` open Medium Dependabot alerts (`#22`–`#28` on `next ^16.4.3`, fixed in `16.4.5`; `#21` on `minimatch`, fixed in `11.0.1`) live exclusively in `website/package-lock.json` (the static marketing/docs site, never imported by `:3102`). All `4` GitHub Actions workflows already pin `actions/checkout`, `actions/setup-node`, and `actions/upload-artifact` to full 40-char commit SHAs.
4. **Multi-Agent Credential & Execution Isolation (Fast-Follow Addendum 01 — Core Strategic Finding):** **`CONFIRMED ARCHITECTURAL EXPOSURE (High Strategic Priority)`.** All active TangleClaw sessions across all fleets (`TC-Lane-*`, `Medusa-*`, `TV-*`, `Monad-*`) execute under a single macOS POSIX account (`uid=501(jasonvaughan)`). While application-layer and `PATH`-wrapper controls (`lib/medusa-send.js` `HTTP 403 CROSS_FLEET_FORBIDDEN`, `~/.tangleclaw/merge-role-guard-wrapper/gh` and `tc`) prevent accidental cross-fleet traffic or unauthorized merges during normal agent operation, **they are not OS-level or cryptographic security boundaries against hostile code execution**. A compromised dependency or prompt-injected builder running as `uid=501` can invoke `/opt/homebrew/bin/gh` directly (using the Operator's `admin:org`/`repo` keychain token) or read `~/.tangleclaw/tangleclaw.db` directly via `sqlite3` to harvest peer `TC_LAUNCH_TOKEN`s.

## 4. Threat Modeling Analysis (Three Required Scenarios)

### Scenario 1 — Compromised `npm` Dependency (`postinstall` or Test Runner Execution in a Builder)
- **Entry Point:** A builder executes `npm install` or `npm test` inside a project workspace containing a compromised transitive dependency.
- **Current Available Privileges:** Arbitrary code execution as `uid=501(jasonvaughan)` with network egress, read/write access to `~/.tangleclaw/tangleclaw.db`, full GitHub CLI keyring access (`/opt/homebrew/bin/gh` with `admin:org`, `repo`), and read access to `~/.claude`, `~/.codex`, `~/.gemini`, and `~/Documents/Projects/*`.
- **Potential Blast Radius:** Exfiltration of model provider tokens and control-plane SQLite secrets; unauthorized pushes or merges across all `Jason-Vaughan` GitHub repositories; cross-fleet workspace tampering.
- **Existing Detection & Prevention:** TangleClaw's core control plane has **zero** npm dependencies; `.github/workflows/*.yml` pin Action SHAs; `#1858` blocks committing SQLite files during session wrap.
- **Security Gaps:** No OS-level filesystem sandbox denying builder child processes access to `~/.tangleclaw/tangleclaw.db`, `~/.config/gh`, or sibling workspaces.
- **Recommended Containment Architecture (`#3212` Phase 1 & 2):** Default to `npm ci --ignore-scripts`; wrap builder shells in a per-seat macOS Seatbelt (`sandbox-exec`) profile denying access to `~/.tangleclaw/tangleclaw.db` and sibling workspaces; replace direct `gh` keyring access with a role-scoped control-plane GitHub broker.
- **Relative Remediation Priority:** **P1 (Phase 1 & Phase 2 of `#3212`).**

### Scenario 2 — Prompt-Injected Agent (Adversarial Issue, PR Diff, or External Document)
- **Entry Point:** An agent reads untrusted repository content, PR text, or external documentation containing instructions to merge unreviewed code, exfiltrate secrets, or message/impersonate another role.
- **Current Available Privileges:** Default shell `PATH` routes `gh`, `tc`, and `tmux` through `~/.tangleclaw/merge-role-guard-wrapper` and `~/.tangleclaw/bin/tmux`, which refuse `gh pr merge` from non-Integrators and refuse cross-fleet Medusa sends (`HTTP 403 CROSS_FLEET_FORBIDDEN`).
- **Potential Blast Radius:** If the prompt injection instructs the agent to invoke `/opt/homebrew/bin/gh pr merge` by absolute path or read `TC-Lane-INT`'s launch secret from `~/.tangleclaw/tangleclaw.db`, the agent can bypass the `PATH` wrapper and application-layer role boundary.
- **Existing Detection & Prevention:** `lib/untrusted-pr-review.js` (`#1554`, `ADR 0014`) fences `<untrusted-pr-data>` and flags suspicious tokens; `lib/medusa-send.js` enforces fleet isolation; `Rule #257` and `Rule #285` enforce coordinator/architect read-only discipline.
- **Security Gaps:** Escaping prevents structural tag breakout but cannot prevent semantic persuasion when the underlying OS process still holds `uid=501` filesystem and keychain authority.
- **Recommended Containment Architecture (`#3212` Phase 1 & 2):** Enforce kernel-level read-only worktrees (`sandbox-exec`) for `architect`, `observer`, and `reviewer` seats; strip `TANGLECLAW_LAUNCH_SECRET` from `tmux` environment tables after bootstrap; broker GitHub merges through `:3102` after verifying SQLite `O-Gate` + `A-Gate` + `R-Gate` receipts.
- **Relative Remediation Priority:** **P1 (Phase 1 & Phase 2 of `#3212`).**

### Scenario 3 — Malicious Third-Party Fleet Pack (`Ruling A893` / `#3194`)
- **Entry Point:** An Operator imports a third-party `fleet-pack.json` containing poisoned `commonRules`, `primingPrompt`, or `mcpServers` commands designed to escalate privileges beyond its declared capabilities.
- **Current Available Privileges:** If launched under the current `uid=501` runtime without Seatbelt or container isolation, the imported fleet's seats would inherit full `uid=501` filesystem and `gh` keychain access.
- **Potential Blast Radius:** Compromise of host credentials and existing private fleets (`TC-Lane-*`, `TV-*`, `Medusa-*`).
- **Existing Detection & Prevention:** `lib/v6/fleet-template-spec.js` enforces data-only JSON validation (`_SAFE_FILENAME_RE`, `_HTTP_URL_RE`); `lib/control-state.js` fences `pendingControlBinds` until Wizard ratification; `Ruling A893` separates `Plane A` (`fleet-pack.json` blueprint) from `Plane B` (`migration-snapshot.sqlite`).
- **Security Gaps:** Declarative capability grants at install time are not yet backed by runtime OS/kernel enforcement.
- **Recommended Containment Architecture (`#3212` Phase 3 & `#3194`):** Quarantine untrusted Fleet Packs to `Plane A` only (reject untrusted `Plane B` SQLite snapshots); require Ed25519 publisher signature + SHA-256 verification; bind the pack's Wizard-approved `capabilities` directly into its per-seat Seatbelt/container profile and scoped GitHub App tokens.
- **Relative Remediation Priority:** **P2 (Required before shipping third-party Fleet Pack imports in `v6.6.0` / `#3194`).**

## 5. Phased Target Isolation Architecture & Recommended Remediation Order (`Ruling A904`)

1. **Immediate (During `v6.5.8` `#3198` / `BUG-002`):**
   - Stage the latest patched Node.js 22 binary into `~/.tangleclaw/bin/node` with `~/.tangleclaw/bin/node.manifest.json` (`version`, `sha256`, `sourcePath`), update `com.tangleclaw.server.plist` and `com.tangleclaw.bridge-helper.plist` to use `~/.tangleclaw/bin/node`, and strip `/opt/homebrew/opt/openjdk/bin` from the LaunchAgent `PATH` — **the `PATH` strip shipped in this PR (`#3211`); the Node binary staging remains tracked under `#3198`.**
2. **Maintenance Hygiene (Bounded `website/` PR):**
   - Bump `next` to `>=16.4.5` and `minimatch` to `>=11.0.1` in `website/package.json` / `website/package-lock.json` to close all `8` open Medium Dependabot alerts (`#21`–`#28`) — **shipped in this PR.**
3. **Phase 1 — Immediate Multi-Agent Credential Hardening (`#3212`):**
   - **Control-Plane GitHub Merge & Release Broker:** Route PR merges exclusively through `:3102` (`POST /api/v6/merge-queue/execute`) after verifying `O-Gate`, `A-Gate`, and `R-Gate` SQLite receipts, removing raw Operator `gh` merge authority from builder shells.
   - **Ephemeral Launch Secret Delivery:** Strip `TANGLECLAW_LAUNCH_SECRET` from long-lived `tmux` environment tables after session bootstrap.
4. **Phase 2 — Per-Role & Per-Fleet OS Execution Isolation (`#3212`):**
   - **Deterministic macOS Seatbelt (`sandbox-exec`) Profiles per Seat:** Deny agent child processes direct filesystem access to `~/.tangleclaw/tangleclaw.db`, `~/.tangleclaw/config.json`, `~/.config/gh`, and sibling fleet roots (`~/Documents/Projects/*` outside the seat's assigned `${SEAT_WORKSPACE_DIR}` and `${FLEET_SHARED_DIR}`), and enforce kernel-level read-only worktrees for `architect`, `observer`, and `reviewer` seats.
5. **Phase 3 — Commercial / Third-Party Fleet Pack Readiness (`#3212` + `#3194` in `v6.6.0`):**
   - Signed `FleetPack` bundles, declarative capability manifests enforced at runtime, short-lived per-seat GitHub App tokens, and optional container/VM worker isolation (`#3005`).
