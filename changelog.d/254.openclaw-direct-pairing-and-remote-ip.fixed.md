- Fixed two `openclaw-direct` proxy accuracy issues (#254). **Issue B:**
  `/openclaw-direct/:connId/*` (both the HTTP and WebSocket proxy handlers
  in `server.js`) now strips stale Cloudflare edge-attribution headers
  (`cf-connecting-ip`, `true-client-ip`, `cf-ray`, `cf-ipcountry`,
  `cf-visitor`, `cdn-loop`) before forwarding to OpenClaw's gateway,
  whenever the connection's own remote address is private/Tailscale/LAN --
  a connection that genuinely arrived via Cloudflare keeps its real
  headers. Closes the gap where a Tailscale-direct pairing recorded a
  Cloudflare edge IP (`172.64.146.15`) as its `remoteIp`. **Issue A:**
  `lib/openclaw-html.js` now injects a small device-identity bootstrap
  into every `/openclaw-direct/` Control UI page load: a stable id, minted
  once and persisted in a TangleClaw-namespaced `localStorage` key, shared
  across every `connId` on this TangleClaw origin (unlike whatever key, if
  any, OpenClaw's own bundle uses) and exposed via
  `window.__tangleclawOpenclawDeviceId` and a `<meta
  name="tc-openclaw-device-id">` tag. This is bridging infrastructure, not
  a guaranteed fix -- whether a given OpenClaw gateway version reads
  either is outside this repo's control.
