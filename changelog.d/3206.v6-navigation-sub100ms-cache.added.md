- Clicking a fleet member, fleet, or workspace tab in V6 Shell now updates the active selection and shows the target route's own loading state immediately, from whatever is already cached, instead of blocking on a fresh sequential reload of projects, engine health and fleet templates on every single click — that refresh now runs in the background instead. Opening a live chat also fires its status, output peek and Medusa-listener reads together rather than one after another, and its conversation history and attestations now start loading the moment the session status is known, rather than waiting on that output peek and listener read to finish first too (#3206).
- Every static "Loading…" text in V6 Shell (chat/settings detail pane, chat history panel, fleet plan/template loading, the usage probe's own refresh/interval status line) now shows a context-specific, accessibly-animated ellipsis indicator — "Loading chat…", "Retrieving history…", "Refreshing usage probe…", and so on — reusing the chat composer's existing ellipsis animation and its reduced-motion handling rather than a plain, unanimated line (#3207).
- Clicking `↻ Refresh now` or changing the auto-refresh interval in the Engine Usage pop-up now actually works — both requests were silently missing a required header and the server refused them outright every time. A provider the automated probe could not read now shows its own error note and last-probed timestamp instead of a bare status badge (#3208).
- The Engine Usage pop-up now groups each engine's provider-reported quota and locally-estimated usage into one clearly labelled card per engine (Claude, Codex, Antigravity), instead of two separate, unlabelled blocks — the refresh/interval controls stay pinned once at the top rather than repeating per engine (#3209).
