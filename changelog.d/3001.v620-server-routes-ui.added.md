- v6.2.0 modules are now live (#3001-#3005), behind the operator gate, through 10 `/api/v6/*` routes: `POST /api/v6/whatif/simulate` and `POST /api/v6/whatif/compare` (what-if simulator); `GET /api/v6/providers/g2b` and `POST /api/v6/providers/g2b/normalize` (GitLab/Jira/Linear/Dolt adapters, exercised offline); `GET /api/v6/advisor/usage` and `POST /api/v6/advisor/advise` (external advisor); `GET /api/v6/medusa-v2/status` and `POST /api/v6/medusa-v2/compact` (Medusa v2 compact wire); `GET /api/v6/sandboxing/status` and `POST /api/v6/sandboxing/plan` (host sandboxing). The server owns every security-bearing input: the advisor reads only under an operator-configured approved-repositories root (`TANGLECLAW_ADVISOR_REPOS_ROOT`), with server-set limits, protected roots and clock, and checks the rate cap before any file is read; sandboxing plans use server-derived host facts and never return the server's environment; the Medusa v2 route encodes, parses and diffs without recording anything. The v6 Fleet Shell adds a Platform view (`#/settings/platform`) with live provider, Medusa v2 and sandboxing status, and a sample what-if simulation (`#/settings/whatif`).
