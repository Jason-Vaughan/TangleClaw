- `lib/project-authority-settings.js` codifies which `DEFAULT_PROJECT_CONFIG` settings belong to the operator — a project session editing `project.json` cannot choose them — versus the project's own checkout. `launchSequence.recoveryMode` is the one operator-pinned setting today (already DB-backed via `store.projectRecoveryState` + `resolveRecoveryMode`, shipped with #1937); every other setting, including `acceptFolderTrust`, `defaultLaunchMode`, `showLaunchModePicker`, and `releaseMode`, is verified project-owned against `server.js`'s real `PATCH /api/projects/:name` admission logic. `resolveProjectAuthoritySettings`/`detectAuthorityDiscrepancy` give callers one audit entry point with zero schema duplication — `recoveryMode` delegates straight through to the existing resolver rather than a second table. `lib/projects.js#enrichProject` now reports `authorityDiscrepancies` per project, and `lib/sessions.js`'s launch-time recovery-mode resolution is routed through this module rather than calling the underlying resolver directly (#1982, Ruling A491-W1D-R3).
