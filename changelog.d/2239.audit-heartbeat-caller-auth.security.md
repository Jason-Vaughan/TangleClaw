- **`POST /api/audit/heartbeat` now authenticates its caller and scopes it to the session it owns, instead of trusting `body.session_id` outright (#2239).** A caller with a verified TangleClaw launch binding could previously heartbeat (and so silence or spoof) any project's watchdog entry by naming another project's `session_id`; nothing checked that the two agreed. Two proofs are now accepted, neither granting any Operator, Master, Medusa or PortHub authority:
  1. An OpenClaw webhook's own `audit_secret` Bearer token, the same proof `/api/audit/ingest` already takes (`401 UNAUTHORIZED` on a missing or wrong one, `409 CONNECTION_UNBOUND` on a valid one with no project bound to it) — this also closes a separate gap: since #2233's launch-binding floor, a remote engine's heartbeat with no binding at all was refused outright (`403 LAUNCH_BINDING_REQUIRED`), so OpenClaw's own heartbeat could never actually reach the watchdog before now.
  2. A verified TangleClaw project launch binding or the operator/Project Master, resolved exactly as every other mutating route resolves one (refusing a stale, unbound or invalid binding with the same code the floor would). `session_id` on this path is TangleClaw's own numeric session id, looked up server-side: a project may heartbeat only a session its own project owns (`403 OTHER_PROJECT` otherwise), an unknown id is `404 NOT_FOUND`, and an ended one is `409 SESSION_ENDED`. The operator and Master may name any project's session.

  `lib/launch-binding-guard.js`'s `EXCEPTIONS` lists the route as `OWN_PRINCIPAL`, the same way and for the same reason `/api/audit/ingest` already is.
