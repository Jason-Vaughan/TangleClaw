- `scripts/test-stage.js`'s Large tier (Stage 5) now runs under a
  `--test-timeout` of its own, so a genuinely stuck file is cancelled and
  named instead of blocking the whole stage indefinitely with no recovery.
  The originally-reported hang in `test/soak-guest.test.js` turned out not
  to be infinite: measured alone end to end before any further fix, it
  passed cleanly (208/208) in ~804s — slow, not stuck.
- Fixed two real causes of that slowness: `deploy/soak/guest/guest-setup.sh`'s
  `bounded()` watchdog deferred its own cleanup for the full probe timeout
  when the probed command exited quickly on its own (a bash signal-delivery
  quirk — a subshell blocked in `wait` for a foreground child does not act
  on a received signal until that wait returns), and `test/soak-guest.test.js`
  created dozens of brand-new executable fake-command files per test, each
  paying a real macOS Gatekeeper/syspolicyd first-execve scan (measured:
  ~230ms for a fresh executable inode vs. ~10ms reusing an already-scanned
  one). Fixed the former by backgrounding the watchdog's own sleep with a
  TERM trap instead of a foreground one with a deferred signal, and the
  latter by symlinking every fake command to one shared, already-scanned
  dispatcher that dot-sources (`.`, a `read()`, never an `execve()`) the real
  per-command logic from a sibling file. Re-measured end to end: 208/208
  pass in ~270s (~3x faster). The Large-tier timeout is set with real margin
  above that measurement but is not yet calibrated against a full Stage 5
  run under real host contention (#2691).
