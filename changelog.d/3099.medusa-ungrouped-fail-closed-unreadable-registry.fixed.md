- A project in no group can no longer reach another fleet's workspace just because that fleet's Medusa registry could not be read (#3099). An ungrouped project may still send to a workspace no local project claims, such as a peer on another host. But while a registry of a project outside its fleet is unreadable (for example, because macOS privacy controls block the folder), such a workspace may really belong to that project, so the send is now refused until the registry reads again. Remote peers are refused during that window too. A broadcast's refusal says why (`details.reason: REGISTRY_UNREADABLE_OUTSIDE_FLEET`) without naming the other fleet, the server log lists every unreadable registry, and `allowCrossFleet: true` still sends.
