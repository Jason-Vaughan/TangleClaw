- A server restart while a launch's first turn was deferred behind an engine startup dialog (folder
  trust, bypass-permissions, etc.) no longer drops that first turn with no trace. The restart is now
  recorded as soon as the server comes back up, through whichever of the launch's two existing
  delivery ledgers it actually used, without disturbing an unrelated eager entry that ledger may
  already carry (a no-rules or silent-prime launch) — a dialog that reappears later, well after the
  session's own first turn already delivered, is correctly left alone rather than misreported as
  dropped. For most launches the drop also surfaces directly in the project's launch-sequence/status
  panel (`GET /api/launch-sequences`), with no change to that endpoint; for a no-rules or
  silent-prime launch specifically, the panel's single delivery slot keeps showing that launch's
  earlier, unrelated entry, and the drop is durably recorded but not yet shown there (#2193).
