- A server restart while a launch's first turn was deferred behind an engine startup dialog (folder
  trust, bypass-permissions, etc.) no longer drops that first turn with no trace. The restart is now
  recorded as soon as the server comes back up: a durable activity-log entry naming the dialog, and a
  delivery-ledger entry that surfaces in the project's launch-sequence/status panel (`GET
  /api/launch-sequences`) as a `skipped` rules delivery, so the drop is visible there instead of
  silent. A dialog that reappears later, well after the session's own first turn already delivered,
  is correctly left alone rather than misreported as dropped (#2193).
