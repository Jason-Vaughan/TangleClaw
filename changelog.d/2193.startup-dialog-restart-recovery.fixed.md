- A server restart while a launch's first turn was deferred behind an engine startup dialog (folder
  trust, bypass-permissions, etc.) no longer drops that first turn with no trace. The restart is now
  recorded as soon as the server comes back up, through whichever of the launch's two existing
  delivery ledgers it actually used, so the drop surfaces in the project's launch-sequence/status
  panel (`GET /api/launch-sequences`) exactly where that launch's own delivery already shows — as a
  `skipped` rules delivery for an ordinary launch, or a withheld pointer-paste outcome for a
  pull-pointer one — with no change to that endpoint. A dialog that reappears later, well after the
  session's own first turn already delivered, is correctly left alone rather than misreported as
  dropped (#2193).
