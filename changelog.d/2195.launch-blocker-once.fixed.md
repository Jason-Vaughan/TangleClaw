- The same engine startup dialog is no longer logged twice as `session.launch_blocked` (#2195). The boot watch records a dialog when it first sees it, and a send holding a session row read before that write could record it again. `store.sessions.setLaunchBlocker` now decides under one write lock: recording the code already stored writes nothing, logs nothing, and returns the session as it stands, keeping when the dialog was first seen. A different dialog, an unreadable stored blocker, and a dialog shown again after it was answered are still recorded.
