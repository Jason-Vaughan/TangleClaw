- Added the canonical Orchestrator role vocabulary contract (#2127, staged
  sequencing: vocabulary and inventory first). `lib/master.js` now exports
  `ORCHESTRATOR_CANONICAL_ROLE`/`_KEY`/`_HANDLE` ("Orchestrator" /
  "orchestrator" / "@orchestrator"), `ORCHESTRATOR_LEGACY_ROLE`/`_KEY`/`_HANDLE`
  ("Project Master" / "master" / "@master"), `resolveOrchestratorRoleIdentifier`
  (exact-match resolution of either vocabulary, never a Git branch name like
  `origin/master`), and a frozen `ORCHESTRATOR_COMPATIBILITY_INVENTORY`
  documenting every retained legacy identifier (`config.master`,
  `session_rules.kind='master'`, `/api/master/*`, the `tc_master_` token
  prefix, the `tangleclaw-master` tmux session, and the two Medusa
  switchboard constants) with its compatibility reason and retirement
  status. An additive `roleTerminology` block now rides on every Master
  status-composition payload (`getMasterStatus`, `getAuthorityState`,
  `evaluateContinuityHealth`) with no existing field disturbed. No display
  copy, persisted column, config key, API route or tmux session name is
  renamed by this change -- those are later, separately scoped stages.
