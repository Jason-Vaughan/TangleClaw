- Sprint reports can now cover a multi-version train and its fast-follow point releases in one place (#3089). Sprint Report Contract v3.1 adds an optional `fast_follow_subversions` list: each small fast-follow release (for example `v6.2.2`–`v6.2.10`) gets one remark row in the parent report's overview or deliverables table, instead of a full report of its own or no record at all. A fast-follow marked as a major learning must also link the Kaizen ledger item it produced and its postmortem entry, and the new validator Rule 11 refuses a report that leaves either out. `buildConsolidatedTrainReportSummary` totals PR counts, issues closed and token economics across a train's versions from one computation, so a consolidated report's totals always match its own rows; a version with no data is named rather than counted as zero, and an incomplete cost total is not stated. `renderConsolidatedTrainSummary` and `renderFastFollowRemarkTable` render both, and `verifyFastFollowKaizenLinks` confirms each linked Kaizen item exists.
