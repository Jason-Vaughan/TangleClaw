- macOS Full Disk Access could be lost across a Homebrew `node@22` upgrade, since the grant is keyed to the resolved Cellar binary path rather than the `which node` symlink `com.tangleclaw.server.plist` has always run — causing stopped sessions under `~/Documents` to fail on launch. Added `scripts/install-fda-anchor.sh --stage`, which stages the active, verified node binary (and its `libnode` dylib) at a stable path (`~/.tangleclaw/bin/node`) that survives every future patch upgrade, so a one-time Full Disk Access grant to that path keeps working; `--status` reports it non-destructively. Added an Operator-run `--cutover` subcommand that refuses to proceed unless the staged binary exists, runs, and actually passes a real Full Disk Access read of `~/Documents` first, then backs up and points `com.tangleclaw.server.plist`'s `ProgramArguments[0]` at the staged binary — the one place in the script that ever writes the plist, and only as this explicit, hand-run step; `--stage` now prints the exact `--cutover` command to run once the grant is made. `GET /api/system/health`'s Full Disk Access check now also reports the resolved node identity and the TCC-authorized tmux server's own health, including real socket readability in production (`lib/system-health.js`, `lib/tmux.js`'s new `probeTccServerHealth`). Fixed (#3198).
