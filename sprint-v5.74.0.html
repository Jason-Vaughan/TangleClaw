  • Finding KR-5740-01 (Preserve All desiredProfile Fields Across Partial Post-Launch Verification · PR #2974 / #2188): In PR #2974 Round 1, `lib/sessions.js#_verifyModelAfterLaunch` called `setDesiredProfile(project.name, { engine, model })` without forwarding `effort`, silently wiping the Operator's selected reasoning effort back to `null` immediately after launch; Round 2 also uncovered an admission deadlock when `requestedModel === null` on an effort-only launch. **Guardrail:** Any post-launch reconciler updating `desiredProfile` must merge existing profile fields (`effort`) rather than overwriting with a partial object, and `_modelAdmissionBlock` must only gate when `requestedModel` is non-null.

  • Finding KR-5740-03 (Pre-Authorize Coordinator Boundary Model Switching Before Multi-Engine Quota Burn Sprints · PR #2973 / #2598): When Builder lanes `TC-Lane-B/C/D` hit the OpenAI Codex usage limit mid-sprint, `TC-Lane-PM` initially received `403 FORBIDDEN` on `POST /api/sessions/:project/switch-model` and `/relaunch` because coordinator authority was not wired on those lifecycle routes, requiring a two-step `PUT /api/projects/:id` + relaunch workaround until `PR #2973` (`#2598`) landed. **Guardrail:** Verified in live Wave 2 execution (`PR #2973` enabled clean boundary transitions).
