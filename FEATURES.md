- **Unreachable-server honesty** (#709/#924/#941) — one policy for what every page does while the server is not answering, and one ceiling past which it stops calling the outage a blip. `public/reconnect-policy.js#tcCreateReconnectPolicy` owns the retry cadence, the jitter, and the ceiling; each page supplies only how to probe and what to render, because the loop used to be duplicated and that is exactly why #709's escalation reached the dashboard and not the session page. The **ceiling is elapsed time, not a count of attempts** — browsers clamp background-tab timers to ~1/min, so an attempt count escalated ~20s into an outage in a foreground tab and ~4min in a backgrounded one, and an operator with several tabs open saw them disagree. Probes are jittered so N tabs do not converge into a burst against a booting server. Deliberately **not** cross-tab coordinated: per-tab state is honest, and the time ceiling removes the visible inconsistency far more cheaply than a shared channel. Escalation shape differs by page *because the pages differ*: the dashboard renders a full-screen card (`public/landing.js#renderUnreachableState`, `.unreachable-state` in `public/style.css`) since nothing beneath it can work; a session renders a **flow banner that shortens the terminal rather than covering it** (`public/session.js#renderSessionUnreachable`, `.session-unreachable` in `public/session.css`) because ttyd is on a separate port and can be alive while the API is gone — covering it would assert what the page cannot establish. Both carry the origin, the cached-shell caveat, the two host-side checks, and an explicit Retry; neither reloads or redirects (no-UI-timers, #98/#268). Outage classification lives in `public/api-helper.js` and covers the SW's synthetic 503 / cache-fallback marker and the Caddy gateway's 502/503/504 (#924), while the server's own `{error, code}` JSON 5xxs stay route errors. `reconnect-policy.js` is network-first in `public/sw.js` — both pages call the factory at parse time, so a stale copy is a `ReferenceError`, not a cosmetic skew. Tests: `test/reconnect-policy.test.js`, `test/landing-unreachable-state.test.js`, `test/session-unreachable-state.test.js`.

- **Rename warns about LaunchAgents still naming the old path** (#1148) — a project-owned LaunchAgent (the supported pattern for a macOS automation that needs a TCC grant) freezes the project's absolute path in its plist, and launchd does not follow a rename. `lib/launchagent-scan.js#scanLaunchAgents` reads every `~/Library/LaunchAgents/*.plist` for the old path at a path boundary (never throws; an absent directory is an empty result; an unreadable plist is listed as unread, not as a non-match), `#formatWarning` turns the result into one sentence naming each job's label and file, and `lib/projects.js#updateProject`'s rename branch carries it as `warnings` — distinct from `errors`, because nothing about the rename failed. `PATCH /api/projects/:name` merges both onto `response.warnings`; the dashboard renders them in a banner that stays until dismissed (`public/ui.js#renderSettingsWarnings`). - **Directory scanner — filesystem work in a killable child** (#883) — every read of an
  operator-chosen path happens in a forked process, never on the server's event loop, because a
  TCC-protected path on macOS never returns a read and a deadline cannot cancel a syscall (it
  abandons the promise and the libuv threadpool thread is gone for good; four of those and the
  server can no longer touch the filesystem at all). Supervisor: `lib/dir-scanner.js` —
  correlation ids, per-request child ownership, `SIGKILL` on the deadline, lazy respawn, and a
  per-path failure backoff (30s → 5min ceiling) that only the polled route opts into. Walks:
  `lib/dir-scanner-child.js#HANDLERS` (`listUnregistered`, `scanEntries`, `createDir`,
  `projectFacts` — which carries existence, governance, git, config and version, and is the one
  handler that WRITES, via version detection's read-time self-heal). Two scanners: a background one for the dashboard poll — `listAllProjects`'s
  walk and the per-project `projectFacts` reads behind `listProjects` — and an interactive one
  for everything an operator pressed a button for: the wizard's
  `scanDirectoryForProjects`/`createProjectsDir`, and every single-project read routed through
  `lib/project-facts.js#readProjectFacts` (which defaults to interactive, so a caller that
  forgets pays a process rather than inheriting a cached refusal). A hung poll therefore cannot
  kill a child out from under an operator's click, and an operator who has just granted Full
  Disk Access is never answered from the backoff. Rejection vocabulary is contractual — `tcTimedOut` (did not answer;
  the sole input to the Full Disk Access advice), `tcCached`, `tcAborted` (collateral),
  `tcTruncated` (ran out of budget). Callers: `lib/projects.js#listAllProjects`,
  `#scanDirectoryForProjects`, `#createProjectsDir`.

- **HTTP requests that are guaranteed to settle** (#1024, #1026) — every `node:http` promise TangleClaw awaits routes through one helper, because settling on `res.'end'` + `req.'error'` is the shape that looks exhaustive and is not. A socket dying **gracefully (FIN)** after headers but before the body fires `res.'aborted'`/`'error'`/`'close'` and nothing request-side, and `req.setTimeout` cannot rescue it — that timer is socket-inactivity based, so it dies with the socket. The promise hangs forever. A socket **destroyed (RST)** raises `ECONNRESET` on the request and was always handled, which is why an RST-based test fixture passes against the bug and proves nothing. Helper: `lib/http-settle.js#requestOnce` (enumerated terminal events → one-shot settle, plus an unref'd wall-clock backstop). Callers: `lib/sidecar.js#_getWithAgent` (rejects), `lib/clawbridge.js#startSession`/`#_requestJson` (resolve-never-reject, mapping a `reason: 'timeout'` back to the bridge's own wording). `lib/tunnel.js` is NOT a caller and does not need to be — it probes via `fetch`+`AbortController`, which rejects on a truncated body and whose timeout is wall-clock. Tests: `test/http-settle.test.js`.
- **OpenClaw tunnel start — bounded, and verified before the frame loads** (#1012) — the tunnel-start `POST` carries an `AbortController` budget so a start that never answers ends instead of hanging under the persistent `Starting tunnel…` toast, and a **pre-flight probe** issues one real request to the proxy base the iframe is about to load. A 5xx there means the proxy's upstream is gone — reported as a TangleClaw failure naming the connection, explicitly *not* a browser/extension problem, because the pre-fix behavior handed the operator OpenClaw's own extension-blaming error card for a TC tunnel drop. Not a spinner timeout: the *request* is bounded, and a probe result replaces the unknown (this project bans timer-driven UI lifecycle, #98/#268). Helper: `public/openclaw-tunnel-state.js#callWithTimeout`/`#probeProxy`/`#describeTunnelFailure`. Consumer: `public/openclaw-view.js#init`, terminal state via `#failTunnel`. Script tag: `public/openclaw-view.html`. The start stays routed through `api()` so the #709/#924 outage checks still apply. Tests: `test/openclaw-tunnel-state.test.js`.

- **Unknown is not a fact — tri-state liveness reads** (#900/#891/#905/#907/#908) — every liveness read has three outcomes (yes / no / could not establish) and the payloads carry all three: `session.active`, `git.dirty`, `master.exists`, and `getSessionStatus`'s `idle`/`lastOutputAge` all report `null` with `incomplete` naming the field and `cause` saying why, never a plausible default. `incomplete` is `[]` on every healthy answer rather than absent, so consumers read a value instead of probing for a field. `tmux.probeSession` → `{live, answered, cause}` is the primitive; `hasSession` is its boolean face, kept for callers about to act on a pane. `POST /api/master/ensure` refuses on an unestablished liveness with its own `MASTER_LIVENESS_UNKNOWN` code, and both master surfaces branch on that code so neither paints an unknown as a definite down. `lib/tmux.js#probeSession`, `lib/master.js#getMasterStatus`, `#ensureMasterSession`, `lib/sessions.js#getSessionStatus`, and `lib/session-ownership.js#_liveness` (#937 — the last read-shaped `hasSession` caller in `lib/`, closing the family; its ownership objects carry `live: null` + `incomplete` + `livenessCause`).
