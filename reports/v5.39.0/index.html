5. Sprint Post-Mortem: What Worked vs. What Didn’t (A474 & Obsr)

Candid synthesis by the Project Manager, Architect (A474), Integrator (TC-Lane-INT), and Sprint Observer (TC-Lane-Obsr) of what succeeded and the 5 concrete process/tooling breakdowns we uncovered during v5.39.0.

✅ What Worked Exceptionally Well (Keep & Codify)

  • 1. #2523 Bottleneck A Fast-Path Slashed Release-Tail CI from ~34m to 70s Total (39s + 31s) Shipping scripts/docs-records-only-diff.js in Wave 1 (PR #2619) paid off inside the same sprint: W3-REC (#2623) passed its 711-test Records Gate in 39s and W4-REL (#2624) passed in 31s, while release.yml still ran the full 23,493-test suite before publishing tag v5.39.0.
  • 2. #2371 Step 3 Stage 1+2 Pre-Push Critic Gate Eliminated the 45m Local Stage-4 Loop Decoupling .claude/hooks/pre-critic-test-check.sh from local Stage-4 allowed both Builders to run Stage 1+2 locally in ~10s before git push and record the 23,488-leaf GitHub Actions JUnit artifact via TANGLECLAW_SUITE_EVIDENCE=ci in ~80s — eliminating the 45-minute local Stage-4 re-run loop seen in v5.38.0.
  • 3. Pre-PR Working-Tree Audit by TC-Lane-INT + Dual Codex PRR-A/B Caught 6 Subtle Bugs on W2-C Before PR #2622 merged, TC-Lane-INT and TC-Lane-PRR-B caught 6 real defects: (a) missing backoff exhaustion-latch reset after manual reconnect, (b) blank terminal buffer misclassified as ended instead of 'unknown', (c) ended-state watcher timer leak on session switch, (d) .mobile-keybar overriding .mobile-keybar[hidden] CSS specificity, (e) .reconnecting class removal ordering in clearReconnectingStatus(), and (f) missing reverse-mode button restoration in undoWebuiMode().
  • 4. Single Consolidated End-of-Sprint W3-REC Replaced Per-Wave W*-REC Serialization Instead of pausing between Waves 1 and 2 for an intermediate W1-REC PR, Builders stayed 100% off shared index files and TC-Lane-INT reconciled all 13 Milestone #24 deliverables in a single W3-REC PR (#2623) that merged in 11m total.

⚠️ What Didn’t Work & Proven Fixes for v5.40.0 (A474 P0–P5)

  • 1. Over-Bundling 5 UI/State-Machine Issues into W2-C Caused a 148m Bottleneck & 2 Interactive AskUserQuestion TUI Freezes While 2–3 issue cars finished in 41m–57m with 0 rework, packing 5 issues (#1317, #960, #1237, #1638, #2011) into W2-C (PR #2622) stretched wall time to 148m. Worse, TC-Lane-C twice invoked Claude Code’s interactive AskUserQuestion TUI menu, freezing the pane at a selection dialog (blocker: "pane-no-prompt") so Medusa wake nudges could not deliver until PM manually injected keystrokes via POST /api/sessions/TC-Lane-C/command. Fix (P0): Cap Builder wave cars at ≤3 UI issues and block AskUserQuestion via a PreToolUse hook in autonomous Builder lanes.
  • 2. W3-REC (PR #2623) Failed First-Pass CI (ccb72417, 22s) Due to verify-features-index.js --base "$BASE_SHA" Cross-PR Blind Spot When TC-Lane-INT opened W3-REC with Tests: anchors pointing to test files added in W1/W2, .github/workflows/test.yml ran node scripts/verify-features-index.js --base "$BASE_SHA" (where $BASE_SHA is origin/main tip). Because those test files were already on main and not in PR #2623’s own git diff, the script rejected them — forcing a workaround commit (5d9d14af) that stripped the literal Tests: prefix from the new FEATURES.md bullets. Fix (P1): Update verify-features-index.js so docs/records-only PRs validate Tests: anchors against on-disk files on main.
  • 3. Unclosed Duplicate Medusa Exchange Triggered a False-Positive prolonged-actionable (60m) Discord Watchdog Alert While TC-Lane-C was busy in W2-C (pane-no-prompt), PM delivered an instruction directly into its pane via /api/sessions/TC-Lane-C/command but left the parallel Medusa exchange open. After 60 minutes unread, the Medusa watchdog fired an operator-needed (prolonged-actionable) Discord alert for work that was already completed. Fix (P2): Enforce immediate tc message close <exchange-id> whenever a pane command or PR merge supersedes an open outbound exchange.
  • 4. macOS TCC Documents/ EPERM Blocked Native tc CLI Invocation in TC-Lane-PM Running node .../TangleClaw-Builder1/bin/tc from inside ~/Documents/Projects/TangleClaw-ProjectManager failed with macOS TCC EPERM: operation not permitted (uv_cwd / open), forcing PM to extract a scratch copy of bin/tc + lib/ outside ~/Documents and run cd /tmp && $TC ... on every turn. Fix (P3): Install the tc CLI entrypoint and runtime libraries into a TCC-safe path outside ~/Documents (e.g. ~/.local/bin/tc or ~/.tangleclaw/cli/).
  • 5. Observer (TC-Lane-Obsr) Re-Bind Report Drift & Missing Post-Mortem Template on Initial Publish After TC-Lane-Obsr was re-bound to Codex GPT-5.4, its initial sprint-v5.39.0.html artifact was stale (still showing W2-C 4/5 in progress, #2011 unfinished, and claiming 100% first-pass CI despite W3-REC’s 22s red) and used a 291-line static layout missing the canonical 7-section interactive structure and What Worked vs. What Didn’t post-mortem. Fix (P4): Add an automated pre-publish structure & KPI verifier for sprint-vX.Y.Z.html before gh-pages push.
