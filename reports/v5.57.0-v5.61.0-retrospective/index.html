What Worked Exceptionally Well Across the Five-Version Train

1. Standing Five-Version Authorization (`OP-GO-V5570-V5610`) + Batch Gate 0 Co-Sign (`[03140778]`)

Co-signing Charters `A494–A498` up front with clear Slice 1 / Slice 2 boundaries allowed the 10-lane fleet to transition seamlessly across 5 release boundaries (`v5.57.0 → v5.61.0`) without waiting for manual Operator re-authorization between legs.

2. Guardrail 06 Two-Version-Ahead Pipelining Compressed Release Wall Time from 5h 36m to 22m (-93.5%)

Instead of leaving Builder and PRR lanes idle during Wave 2 release cuts and live `:3102` updates, `TC-Lane-PM` dispatched the next version's Wave 1 cars early while holding merges until the preceding version tagged. By Leg 5 (`v5.61.0`), all 4 feature cars (`#2863, #2868, #2869, #2865`) were pre-certified and merged in 47 seconds.

3. Defense-in-Depth Bridge Outbound Guard Suppressed 52 Historical `#2853` Backfill Events on v5.61.0 Boot

When `v5.61.0` booted on `:3102` and `_operatorResolved()` backfilled `192` historical resolved exchanges, `TC-Lane-PM`'s outbound bridge guard automatically intercepted and dropped `52` stale notifications with `drop_code='historical-backfill-suppressed'` in `bridge_outbound`, preventing any Discord notification flood.

4. Pre-Staged Parameterized Report Generators (`gen_v5580.py–gen_v5610.py`) & 100% Remote Testament Pool

Pre-staging each version's HTML report generator during Wave 1 reduced Gate 4 (`O-Gate`) turnaround to under 2 minutes after `:3102` deploy, while `Guardrail 10` (100% remote Testament `0.34.0` pool execution) kept Mac Studio host CPU contention at zero across all 26 PRs.

What Didn't Work & Concrete Guardrail Fixes Enacted Across v5.57.0 → v5.61.0

1. Post-Deploy `#2853` Observation: Unbounded `_operatorResolved()` Historical Backfill on First Boot (192 Exchanges / 52 Dropped)

On first boot of `v5.61.0`, `_operatorResolved()` scanned historical resolved exchanges without a lower-bound timestamp window, generating `192` resolved events (`52` of which `TC-Lane-PM` dropped with `drop_code='historical-backfill-suppressed'` in `bridge_outbound`). Fix / Guardrail: Bound `_operatorResolved(since)` by the reconciler window (`lastReconciledAt` / startup high-water mark) so cold boots or schema upgrades only evaluate exchanges resolved within the active reconciler window.

2. Shared Registry File Contention (`docs/areas.json`, `.testament.toml`, `test/tiers.json`) Across Parallel Wave 1 Cars

Because nearly every feature car added new `lib/*.js` modules and `test/*.test.js` suites, merging Car 1 required syncing `origin/main` into Cars 2–4 before merge. Fix / Guardrail: Keep `docs/areas.json` and `test/tiers.json` sorted alphabetically and have `TC-Lane-INT` or Builders perform a 30-second `git merge origin/main` immediately after each serialized merge.

3. Mid-Train Slice 2 Follow-Up Tickets Defaulting Into Active Train Milestones (#45 Noise Resolved by Ruling A497-S1)

Filing Slice 2 follow-up tickets from Legs 1–3 into Milestone `#45` (`v5.60.0`) created temporary scope ambiguity until Architect Ruling `A497-S1` re-milestoned Slice 2 follow-ups to Milestone `#51` (`v5.66.0`). Fix / Rule: Always route newly discovered Slice 2 follow-up issues to a post-train integration milestone (`Milestone #51`) so active train milestones track their exact chartered Slice 1 scope to `0` open issues.

4. GitHub GraphQL Rate-Limit Exhaustion During High-Frequency Multi-Lane PR Polling

During rapid multi-version execution, `gh pr view` (GraphQL) hit hourly rate limits while REST `gh api` still had 4,800+ requests remaining. Fix / Guardrail: Use REST `gh api repos/:owner/:repo/pulls/:num` and local `git log` / `git show` exclusively for Gate 1–4 inspections.
