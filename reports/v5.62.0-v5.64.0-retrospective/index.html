What Didn't Work & Concrete Guardrail Fixes Enacted Across v5.62.0 → v5.64.0

1. Recurring Service Worker `CACHE_NAME` Misses When Adding New `public/*.js` Browser Modules

Four separate UI wiring cars (`#2879, #2890, #2895, #2891`) added new `public/*.js` scripts to `CACHE_FIRST_PATHS` in `public/sw.js` without bumping `CACHE_NAME` on Round 1. Fix / Guardrail: Add a deterministic unit test assertion in `test/service-worker.test.js` that hashes the `CACHE_FIRST_PATHS` list against `CACHE_NAME`.

2. Shared Registry File Contention (`docs/areas.json`, `.testament.toml`, `test/tiers.json`) Across Pipelined Cars

Because all 11 feature cars registered new `lib/*.js` and `public/*.js` files in `docs/areas.json` and `test/tiers.json`, merging Car N required a fast ancestor merge into Car N+1. Fix / Guardrail: Keep `docs/areas.json` and `test/tiers.json` sorted alphabetically and perform an immediate `git merge origin/main` after each serialized merge.

3. Unescaped Backticks in Double-Quoted `gh api -f body="..."` Shell Commands

Posting Markdown comments via double-quoted `gh api -f body="..."` allowed `zsh` to evaluate backticked identifiers before `gh` ran. Fix / Guardrail: Always pass Markdown bodies to `gh api` using single quotes (`-f body='...'`) or `--input `.

4. Cross-Repo Issue Classification (`#2347`) Discovered After Gate 0

Issue `#2347` targeted `Jason-Vaughan/Medusa` rather than `TangleClaw`, requiring mid-sprint deferral (`Ruling A499-W1D-R1`). Fix / Guardrail: Verify target repository ownership during Gate 0 triage before assigning issues to a TangleClaw builder car.
