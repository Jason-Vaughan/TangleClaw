What v5.47.1 Does in Everyday Terms — and How the Team Built It

🛠️ What We Shipped (Reliable Wake-Up Messages for Antigravity & Faster Retries)

1. Clearing stuck wake-up text in Antigravity using the right shortcut keys (#2716 Part 1): Sometimes TangleClaw types a short wake-up notification into an AI agent’s chat box, but the agent’s screen is briefly busy when TangleClaw presses Enter—leaving that notification sitting unsubmitted in the input box. Before trying again, TangleClaw clears the input box. Previously, TangleClaw always pressed Ctrl+U to erase the line, which works in standard terminals (like Claude Code and Codex) but in Antigravity actually scrolls the chat history half a page up instead of clearing the text! Because the old text stayed in the box, TangleClaw refused to type over it and got stuck waiting. In v5.47.1, TangleClaw uses Antigravity’s native clear-line keys (Ctrl+A to jump to the start of the line, then Ctrl+K to delete to the end) while keeping Ctrl+U for all other engines.

2. Retrying missed wake-ups in ~8 seconds instead of waiting up to a full minute (#2716 Part 2): When TangleClaw notices that a wake-up message wasn’t accepted by the agent’s input box, it used to wait up to 30 seconds for a background watchdog timer to notice, and then wait again for periodic background checks before re-sending. In v5.47.1, the moment a wake-up attempt isn’t accepted, TangleClaw immediately triggers its safety budget check and schedules the exact 4-second quiet-screen checks needed to retry right away—recovering missed wake-ups in ~8 seconds while keeping all existing retry limits and cooldown rules intact.

Section 01 · Architectural Deep-Dive

How v5.47.1 Solves Stranded Antigravity Nudges & Unaccepted Medusa Wake Recovery

During v5.47.0 live operations, two interacting behaviors delayed switchboard wake delivery on Antigravity and other busy panes: first, when a switchboard nudge was left unsubmitted in an Antigravity composer, clearPromptLine sent C-u, which Antigravity’s viewport consumed as half-page scroll-up instead of clearing the composer; second, when _verifyWake detected nonce-in-composer and recorded wake_not_accepted, recovery waited for the periodic 30-second watchdog timer and periodic wake poll ticks. Sprint v5.47.1 fixes both root causes cleanly across three modules.

PILLAR 01 · ENGINE-AWARE PROMPT LINE CLEARING (lib/tmux.js#_lineKill)

Antigravity Composer C-a C-k vs. Readline C-u

In Antigravity’s TUI, the top-level viewport intercepts Ctrl+U (C-u) as KeyHalfPageUp before it reaches the embedded charmbracelet/bubbles/textarea composer widget. As a result, calling clearPromptLine on a stranded [TangleClaw Switchboard] ... (wake ref <nonce>) line scrolled the pane upward while leaving the stranded nudge text intact inside the composer, causing subsequent wake scans to repeatedly defer with stranded-nudge-residue. In W1-A (PR #2717), lib/tmux.js#_lineKill(engineId) returns ['C-a', 'C-k'] (LineStart + DeleteAfterCursor in bubbles/textarea) when engineId === 'antigravity' and ['C-u'] for all other engines. Both clearPromptLine(sessionName, engineId) and clearDraftAndSendLiteral(sessionName, text, opts) thread engineId from lib/medusa-wake.js so Antigravity composers are cleared deterministically before retry.

PILLAR 02 · IMMEDIATE DURABLE RE-ARM ON WAKE_NOT_ACCEPTED (lib/medusa-watchdog.js#rearmWorkspace)

Zero-Wait Handoff from _verifyWake to Bounded Watchdog Re-Arm

Previously, when lib/medusa-wake.js#_verifyWake inspected the pane VERIFY_DELAY_MS (1,200 ms) after injection and saw the wake nonce still sitting in the composer (nonce-in-composer), it recorded a durable wake_not_accepted receipt in medusa_wake_state and exited—leaving the workspace un-armed until the periodic MedusaWatchdog timer ran up to 30,000 ms later. In v5.47.1, lib/medusa-watchdog.js#rearmWorkspace(workspaceId) exposes the single-workspace durable re-arm check, and server.js wires onWakeNotAccepted: (wsId) => medusaWatchdog.rearmWorkspace(wsId) into MedusaWakeMonitor. The moment _verifyWake records wake_not_accepted, it invokes onWakeNotAccepted(wsId) synchronously, running the exact same durable budget (maxRearms = 5), exponential backoff (minRearmAgeMs), and unread-message checks that the periodic watchdog uses on server restart.

PILLAR 03 · REMAINING OBSERVATION-GAP CHAINING (lib/medusa-wake.js#_bookFollowUp)

Bridging the 4,000 ms Minimum Observation Gap & Two At-Rest Prompt Looks

Re-arming immediately at t = +1,200 ms after injection exposed a subtle timing interaction caught during B-Gate review: rearmWorkspace calls wakeMonitor.requestScan(), which fires an immediate look at t = +1,200 ms. However, _observePane enforces MIN_OBSERVATION_GAP_MS = 4,000 ms between valid looks (recorded at injection time t = 0), so the look at +1,200 ms returns gap < minGap and was previously dropped without booking a follow-up timer! In lib/medusa-wake.js#_bookFollowUp(wsId, gapDone, delayMs), when a prompt look is rejected solely because gap < minGap (`reason === 'min-observation-gap'`), the monitor books a timer for the exact remaining gap (minGap - gap, ~2,800 ms) as a prompt look (_promptLook.add(wsId)), and once that first at-rest look succeeds at t ≈ +4,000 ms, chains the second at-rest look at t ≈ +8,000 ms to clear the residue and deliver the wake without waiting for any periodic poll tick.

When transitioning rapidly from v5.47.0 wrap to v5.47.1 kickoff, TC-Lane-B began editing lib/tmux.js while its checkout was still on cd09db00 instead of running git fetch origin main && git checkout -B ... origin/main first. Fix / Guardrail (P43): Builders must execute git fetch origin main && git rev-parse HEAD origin/main and verify exact match with the Charter base SHA before touching any file.

2. PRR-A Round 1 Missed the Cross-Timer Interaction Between _verifyWake and _observePane

TC-Lane-PRR-A accepted c4206aba because the unit tests in c4206aba used minObservationGapMs: 0, masking the fact that in production VERIFY_DELAY_MS (1,200 ms) is smaller than MIN_OBSERVATION_GAP_MS (4,000 ms). Fix / Guardrail (P44): Timer and state-machine tests must include at least one test using production-ratio constants (verifyDelayMs < minObservationGapMs) rather than zeroed gaps.

3. Intermediate Fix Commit (be8b7002) Pushed Before Running Exchange-Proof Test Locally

Commit be8b7002 booked a full minGap delay instead of the remaining minGap - gap delay and broke an assertion in test/medusa-wake-exchange-proof.test.js, causing 1 red CI run (40960015900) before 03a33cad fixed it 22 minutes later. Fix / Guardrail (P45): Run all sibling test files in the same subsystem (test/medusa-*.test.js) locally before pushing a review-round fix commit.

4. Review-Process Attribution in Code Comments Needed Cleanup Commit (8b891bc6)

Commit a80865e7 included review-round commentary in source comments, requiring a follow-up cleanup commit (8b891bc6) to keep shipped comments focused on domain invariants. Fix / Guardrail (P46): Code comments must explain timeless product invariants (why the code works this way), never PR review round history.
