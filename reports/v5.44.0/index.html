✅ What Worked Exceptionally Well (Keep & Codify)

  • 1. Zero Same-Wave Rebases Across All 6 Builder Cars via W1-F1_v542 Disjoint Partitioning & Deferred .prawduct/change-log.md (36.5m Mean Build Time) Enforcing 100% pairwise file-disjoint car scopes in Wave 1 (W1-A ∩ W1-B ∩ W1-C ∩ W1-D = ∅, with only W1-D touching server.js) and Wave 2 (W2-A ∩ W2-B = ∅, with only W2-A touching server.js) — combined with catching and reverting an early .prawduct/change-log.md edit on W1-B (#2670) R1 so all records reconciliation happened once in W3-REC (#2676) — achieved 0 same-wave rebases across all 6 Builder PRs and cut mean Builder build time to 36.5m.
  • 2. Multi-Round R-Gate State-Machine & Security Catches on #737, #1223, #1555 & #1368 (0 Post-Merge Regressions) TC-Lane-PRR-A and TC-Lane-PRR-B caught 7 subtle state-machine and security defects before merge: (a) on W2-B (#2674, #737), R1 ensured _bundledEnginesFingerprint is committed only after _syncBundledEngines finishes writing, and R2 gated fingerprint commit on allBundledFilesReadable so swallowed source-read errors retry on the next read; (b) on W2-A (#2675, #1223), R1 enforced operatorProjectCaller admission and the behind-origin kill switch on POST /api/update/pull; (c) on W1-D (#2672, #1368), R2 hardened _checkPublicAssets with statSync.isFile() + accessSync(R_OK) and narrowed the restart exec guard to self-SIGTERM; and (d) on W1-C (#2671, #1555), R1 required plist existence in confirmRestartMechanism and last-poll state in pollServerBackAndReload.
  • 3. Cross-Car Semantic Compatibility Review by TC-Lane-Arc Prevented a Wave 1 Merge Interaction Between W1-C and W1-D Even when two parallel cars are 100% file-disjoint on disk, semantic changes in one module can affect callers tested in another car. During Wave 1 A-Gate review, TC-Lane-Arc spotted that W1-C (#2671)’s new active process-manager ownership check in confirmRestartMechanism() (lib/server-info.js) would be invoked by W1-D (#2672)’s POST /api/server/restart route tests in test/system-health.test.js, and had TC-Lane-D stub confirmRestartMechanism alongside detectRestartMechanism on R1 (86cafc05) before either PR merged.
  • 4. Fast 6.9m Wave 3 Documentation & Index Reconciliation (PR #2676) with 16/16 Tests: Citations Verified on First Pass Deferring FEATURES.md, .prawduct/change-log.md, and docs/user-guide.md to a single consolidated W3-REC pass on TC-Lane-INT allowed PR #2676 (24013995) to open in 3.9m and merge in 3.0m (6.9m total) with all 16/16 newly cited Tests: anchors passing node scripts/verify-features-index.js (P1) and 0 duplicate archive headings (P10) on the first review round.

⚠️ What Didn’t Work & Proven Fixes for v5.45.0

  • 1. Pre-Existing Malformed VRF-006 / VRF-007 Entries in Out-of-Scope .prawduct/operator-verification.md Blocked /prawduct:pr Step 2b (Finding W1-F1_v544) When Builders invoked /prawduct:pr Step 2b (check-operator-verification), pre-existing malformed entries VRF-006 and VRF-007 in .prawduct/operator-verification.md caused the wrapper check to exit non-zero even though .prawduct/operator-verification.md was outside the cars’ authorized file scopes. Lanes bypassed the wrapper via direct git push -u origin <branch> && gh pr create per P20. Fix / Guardrail for v5.45.0 (P21): Repair or retire malformed legacy entries VRF-006 and VRF-007 in .prawduct/operator-verification.md in Wave 1 of v5.45.0 and keep direct gh pr create authorized whenever .prawduct/operator-verification.md is out of scope.
  • 2. Repo-Wide Singleton Escaper (#1399 lib/shell-word.js) & Test-Tier Invariants Caught in CI on W2-A R3 (PR #2675, Finding W2-F1_v544) On W2-A (#2675) R2/R3, adding an inline POSIX single-quote helper in lib/behind-origin.js triggered repo-wide guard test test/engines-hook-shell-safety.test.js (which enforces #1399: lib/shell-word.js must remain the sole POSIX shell-word escaper in lib/), and importing child_process in test/behind-origin.test.js exceeded its medium tier capability ceiling in scripts/test-tiers.js --check. Fixed in R4 (e90a79cb) by importing shellWord from lib/shell-word.js and keeping test/behind-origin.test.js pure-mock in the medium tier. Fix / Guardrail for v5.45.0 (P22): Mandate require('./shell-word').shellWord for any shell quoting in lib/ and require Builders to run node scripts/test-tiers.js --check + node --test test/engines-hook-shell-safety.test.js before every push.
  • 3. Redundant Full /prawduct:critic Invocations on Small R2/R3 Review Fix Commits Added ~12 Minutes of Turn Latency (Finding W1-F2_v544) Running the full multi-persona /prawduct:critic skill after small, targeted 5–15 line R-Gate/A-Gate follow-up fixes on R2/R3 consumed ~10–12 minutes per revision before PM explicitly authorized bypassing /prawduct:critic on R3/R4 follow-up commits once R1 Critic had already completed. Fix / Guardrail for v5.45.0 (P23): Codify that /prawduct:critic runs once before R1 PR creation; targeted R2+ review-fix commits skip redundant /prawduct:critic re-runs and go straight to unit tests + test-tiers.js --check + git push.
  • 4. Cross-Platform Mock Reset Inside Loop Failed on Linux Runner in W1-C (PR #2671 R1, Finding W1-F3_v544) In W1-C (#2671) R1 (e580a987), a new manual-start loop test in test/server-info.test.js stubbed _deps.existsSync and _deps.execFileAsync once before a for loop whose finally block called _resetDepsForTest() on the first iteration — passing on macOS for iteration 1 (`darwin`) but failing on the Linux CI runner during iteration 2 (`linux`). Fixed in R2 (e19a4079) by re-stubbing _deps inside each loop iteration. Fix / Guardrail for v5.45.0 (P24): When a parameterized test loops over ['darwin', 'linux'] with a finally { _resetDepsForTest() } block, always initialize _deps stubs inside the loop body rather than outside.
