Issue-by-Issue Architectural & Contract Deep-Dive (v5.48.1)

ISSUE #2733 · TESTAMENT V0.30.0 DISTRIBUTED CONTAINER POOL INTEGRATION

Project-Scoped Container Image, Tier Routing & Automatic Local Fallback

Authored .devcontainer/Dockerfile (node:22-bookworm with build-essential, python3, git, sqlite3, procps, and lsof) and .testament.toml (schema_version = 1, project_id = "tangleclaw", executor = "container", [tiers.small] max 2 files / 20,000ms budget / 60s timeout, [tiers.medium] max 1 file / 40,000ms budget / 120s timeout, [tiers.large] max 1 file / 180,000ms budget / 300s timeout). Updated scripts/test-stage.js to probe testament status --json at startup for Stages 3–5 when TESTAMENT_DISABLE=1 is not set: if the coordinator is reachable and connected runners are available, scripts/test-stage.js executes testament run --tier <small|medium|large> --files <csv> on the distributed pool and automatically falls back to local node --test execution with a clear diagnostic banner if the pool is unreachable or returns non-zero.

ISSUE #2706 · STAGE 5 PER-FILE TIMEOUT & TIER BUDGET CALIBRATION

Eliminating False-Red Timeouts on Heavy E2E & Lifecycle Suites

Calibrated STAGE_DEFS[5].timeoutMs in scripts/test-stage.js from 60_000ms to 90_000ms and synchronized scripts/test-tiers.js and test/tiers.json so that large multi-session SQLite/PTY/worktree tests (test/e2e-critical-paths.test.js, test/server-session-lifecycle.test.js, test/session-wrap-routes.test.js, test/api-routes.test.js) have deterministic headroom both locally under SUITE_SLOT and inside distributed containers. Added contract tests in test/test-stage.test.js and test/test-tiers.test.js verifying pool probe routing, TESTAMENT_DISABLE=1 bypass, non-zero pool fallback, and tier budget synchronization.

ISSUE #2723 · CODEX SYSTEMERROR TERMINAL TURN-SETTLEMENT RECOVERY

Preventing Permanent Wake Starvation After Model Capacity Errors

In lib/startup-control-codex.js, when Codex emits a terminal codex/event/error or error notification with willRetry === false (or no retry scheduled, such as "Selected model is at capacity. Please try a different model.") while an active turn is in flight and no turn/completed notification arrives within the settlement grace window, the adapter now transitions turnInFlight to false, clears the stuck activeTurnId, records lastTerminalSystemError telemetry, and notifies the wake scheduler so queued switchboard wakes and nudges are delivered instead of stalling forever on pane-turn-in-flight.

ISSUE #2726 · MEDUSA RETARGETED EXCHANGE REPLY RESOLUTION

Accepting Replies From the Live Retargeted Recipient Session

When a Medusa message addressed to a rotated or replaced workspace handle (e.g. tc-lane-pm-old) is automatically retargeted at send time to the live replacement workspace handle (e.g. tc-lane-pm-new), medusa_messages.to_workspace_id and medusa_exchanges.recipient_workspace_id are now synchronized with the resolved live target and persisted alongside retargeted_from_workspace_id in lib/store.js, lib/medusa-send.js, and lib/medusa-exchanges.js. When the live recipient replies via tc message send --in-reply-to <id>, exchange resolution matches both the live retargeted recipient and the original sender without throwing 404 REPLY_TARGET_UNKNOWN.
