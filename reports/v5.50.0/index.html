📖 Plain-English Summary — What Sprint v5.50.0 Accomplished & Why It Matters Written for operators, stakeholders & non-specialist readers

Live Engine & Model Compatibility, Cross-Engine Model Switching, and Usage Quota Visibility

When an operator manages a fleet of AI coding sessions across Claude, Codex, Gemini/Antigravity, Aider, and OpenClaw, switching models mid-session or hitting a rate limit used to require manual restarts or engine-specific guesswork. Sprint v5.50.0 (“Engine and model compatibility”) delivered 10 issues across 8 pull requests (+12,573 / -155 LOC) that make model switching, engine health, and quota windows seamless across every supported engine:

1. Live Model Switching & Automatic Fallback Chains (`#1897`, `#2599`, `#2598`)

We mapped how every AI engine switches models (`#1897`: in-band `/model` slash commands for Claude, Codex, and Aider vs flag-based relaunch for Gemini/OpenClaw), built a unified runtime model-switch engine (`#2599`, SQLite schema_version=75) with git dirty-worktree safety checks, and added ordered model fallback chains (`#2598`) that automatically switch to the next backup model when a session hits a rate-limit or capacity error.

2. Engine Inventory UI, Quota Windows & Profile Drift Alerts (`#2747`, `#2188`, `#1967`)

Building on v5.49.0’s inventory API, we shipped the browser Engine Inventory panel, project-creation defaults, and TangleTweaker docking (`#2747`); added a 5-hour / 7-day rolling usage-window and quota estimator (`#2188`, `GET /api/usage-windows`); and added a periodic CLI help-flag reconciler (`#1967`) that detects when an upgraded AI CLI changes its flags or version.

3. Non-Claude Hooks, Antigravity Prime Hardening & Container Pool (`#2439`, `#1644`, `#1809`, `#2752`)

We shipped a git-backed post-commit governance hook adapter (`#2439`) so Codex, Gemini, and Aider enforce the same commit/record rules as Claude; hardened Antigravity’s post-/clear prime injection against TUI modal swallows (`#1644` / `#193`); documented OpenClaw’s clean-start contract (`#1809`); and added procps (/bin/ps) to .devcontainer/Dockerfile (`#2752`) for Stage 5 Linux container parity.
