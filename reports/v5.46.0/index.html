Section 01 · Architectural Deep-Dive

How v5.46.0 Governs Release Authority, Group Ownership & Wrap Merge Policy

Before v5.46.0, unconfigured projects defaulted to autonomous auto releases, multi-repo project groups lacked single-owner release exclusion, managed projects had no first-class release automation helper, and wrap merge strategy was hard-coded to squash. Sprint v5.46.0 unifies these contracts across configuration, wrap steps, release readiness, and store accessors.

PILLAR 01 · RELEASE MODE & GROUP AUTHORITY (#1701, #1702, #1697)

Explicit Release Authority & Single-Owner Project Groups

W1-D (#2689) renamed releaseMode values from auto/ask to canonical agent / operator / off while preserving permanent read/write normalization aliases for legacy callers and existing SQLite rows. W2-A (#2695) then flipped the unconfigured default from 'agent' to 'operator' (or 'off' when another member of the same projectGroupId already holds release authority) and enforced two-site group ownership: (1) API/store rejection with 409 CONFLICT when a second group member attempts to enable agent/operator or release:cut, and (2) a fail-closed check in lib/wrap-steps/version-bump.js using canonical configRootOf(ctx) so non-owner group members skip version-bump and tag publication even from linked worktrees.

PILLAR 02 · MANAGED RELEASE AUTOMATION & CHANGELOGS (#721, #1051, #2523, #2022)

Dry-Run Release Planner, Git-Blob Tagging & Keep-a-Changelog Links

W2-B (#2694) introduced lib/release-automation.js with three opt-in primitives for TangleClaw-managed repositories: planRelease() (side-effect-free version calculation across version.json, package.json, and pyproject.toml), applyRelease() (fail-closed validation against committed git blobs via git cat-file -e before annotated tag creation), and generateReleaseWorkflow() (GitHub Actions workflow template). Alongside this, W1-D (#2689) added Keep-a-Changelog bottom comparison link references ([Unreleased] and [X.Y.Z]) during promotion, W1-B (#2690) removed the pre-v5.44.0 transition bypass from changelog-update, and W2-B (#2694) taught global rules to inspect project changelog conventions before editing.

PILLAR 03 · WRAP MERGE POLICY, READINESS & STORE GUARDS (#1172, #2162, #1495, #2681, #660)

Configurable Wrap Merge Method, Issue-Closed Signals & Store Key Safety

W1-C (#2687) added configurable wrapMergeMethod ('squash' | 'merge' | 'rebase', defaulting to 'squash' for managed projects) in lib/wrap-steps/pr-merge.js and adjusted commit.js verification accordingly, while recording in ADR 0002 and CLAUDE.md that TangleClaw’s own repository uses guarded gh pr merge --merge. W1-A (#2692) added default-on linkedIssueClosedSignal advisories in lib/release-readiness.js (fetching 100 recent merged PRs and inspecting up to 25 PRs with closing keywords) and completed _assertKnownKeys enforcement across all 15 remaining lib/store.js methods so typoed filter keys throw ERR_UNKNOWN_OPTION_KEY instead of silently matching everything.

What Worked, Friction Points & 16-Point Governance Verification

Every friction event observed during Waves 1–4 was traced to root cause, resolved in-sprint without any revert on main, and paired with a concrete guardrail for v5.47.0.

✅ What Went Well (Strengths)

1. Proactive Observer P22 Catch Saved a Full Review Cycle (A481-R1)

During the Wave 1 batch-start audit, TC-Lane-Obsr flagged that W2-B’s planned test/release-automation.test.js [NEW] would trip P22 (MAX_TEST_FILES = 152 ceiling). TC-Lane-Arch ratified A481-R1 before Wave 2 launched, folding #721 tests into test/changelog-notes.test.js with zero rework.

2. Strict P27 Enforcement Rejected Self-Waiver Shortcut (A481-R8)

When TC-Lane-C’s first local full-suite run hit 13 transient failures caused by concurrent sibling test processes, TC-Lane-INT requested a charter waiver (A481-R8). TC-Lane-Arch rightly rejected A481-R8 under P27, and an isolated re-run passed 152/152 files cleanly.

3. Codex gpt-6-astra (medium) Prevented 6 Subtle Production Bugs

In Wave 2, gpt-6-astra (medium) caught 3 blocking bugs in W2-B (#2694) and 3 blocking group-ownership bypasses in W2-A (#2695) with 60–120s follow-up turnarounds and zero false-positive blocks.

4. Clean Wave 3 Reconciliation & 13/13 FEATURES.md Anchor Pass

W3-REC (#2700) reconciled all Waves 1–2 user/config docs and verified all 13 Tests: file paths in FEATURES.md on disk, closing follow-up issue #2693 in 14 minutes.

⚠️ What Didn't Work (Friction Points & Remediations)

1. Cross-Lane Child Process Contention on Shared Host

Concurrent npm test runs across 4 worktrees spawned competing server/SQLite processes, causing 13 transient failures in W1-C’s first full-suite run. Fix / Guardrail (P29): Serialize full-suite Gate 2 runs or scope process-table assertions by child PID tree rather than global pgrep.

2. Pre-Existing Local Full-Suite Blockers Required Two Waivers

Four pre-existing local-only test failures (#2691 UI layout regex + #2696, #2697, #2698 macOS symlink/worktree path mismatches) blocked un-waived local full-suite runs on W1-A and W2-A, requiring one-PR waivers WAIVE2692 and WAIVE2695. Fix / Guardrail (P31): Prioritize fixing #2691, #2696–#2698 in Wave 1 of v5.47.0.

3. GitHub Post-Squash Merge-Base Lag on W2-A (#2695 / #2699)

After W2-B (#2694) merged, GitHub’s PR comparison cache briefly showed already-merged W2-B files inside W2-A (#2695), prompting a 15-minute fallback PR (#2699) before #2695 auto-refreshed. Fix / Guardrail (P33): Wait 60s or trigger an empty commit/base toggle before opening a replacement PR.

4. Stale PM Plan Snapshot vs Ratified Charter Addenda

TC-Lane-PM’s local plan file was written at 17:58Z and never refreshed after A481-R1..R7, leading W2-B to briefly delete test/global-rules.test.js to stay under MAX_TEST_FILES=152 until PRR-B caught it in R2. Fix / Guardrail (P32): Require lanes to treat the Architect’s ratified charter addenda as authoritative over static plan snapshots.
