# Spec — Master startup and wrap

**Status:** RATIFIED by the operator 2026-08-16. All rulings below are decided, not proposed.
**Owns:** #768 Q1 ("what does Wrap mean for the Master?"), and the memory model behind it.
**Written here** because the design is dominated by mechanism only this repo can see; the
TangleClaw-Roadmap session agreed and took the sequencing question instead.
**Shared copy:** https://claude.ai/code/artifact/a3abddeb-645a-41e1-b645-6e29eee3420b — keep this
same link updated in place as the spec evolves; this file stays canonical.

---

## The one-sentence answer

**The Master's wrap is the same pipeline as a project's, with the git-shaped steps skipped for a
stated reason — not a different thing that happens to share a name.** Seven of the fourteen default
steps apply to the Master, and seven are structurally impossible. The machinery to express that
already exists.

That matters because the failure mode #768 named is shipping a button that *looks* like session
Wrap and does something materially different. Making it the same pipeline, honestly reduced, is the
only version where the button means what it says.

---

## What already exists (verified, not recalled)

Three quarters of what this spec needs is built. Naming it precisely keeps the work small.

**The two-zone memory split is already shipping.** `lib/master.js#_refreshMasterMemory` writes
`~/.tangleclaw/master/memory/`:

| File | Owner | Lifecycle |
|---|---|---|
| `FLEET.md` | TangleClaw | Overwritten on **every** master ensure. Stamped *"Generated by TangleClaw — do not edit."* |
| `HOWTO.md` | TangleClaw | Same. |
| `MEMORY.md` | the Master | Seeded once when absent, never touched by TC again. |
| `NOTES.md` | the Master | Same. |
| `CHANGELOG.md` | the Master | Same — described in-file as *"my activity log"*. |

That is exactly the derived/observed split. It did not need inventing.

**TangleClaw already writes a generated file into every managed project.**
`lib/sessions.js:2797` writes `.tangleclaw/session-prime.md` on every launch. So a second
TC-maintained file in that directory sets no new precedent and needs no new plumbing decision about
where project-local generated state lives.

**The wrap pipeline already models an honest skip.** `lib/wrap-pipeline.js:32` — every step returns
`status: 'done' | 'blocked' | 'skipped'`, and skipped carries a reason. Projects already vary which
steps run through `wrapStepOverrides` (`lib/project-config.js:91`).

**TangleClaw already computes per-project state, including its unknowns.** A live
`GET /api/projects` record carries:

```
git:     { branch, dirty, lastCommit, lastCommitAge, latestTag, incomplete[], cause }
session: { active, status, startedAt, tmuxSession, incomplete[], cause }
version, engine, governanceState, groups, medusaEnabled, ports, archived,
unreadable / unreadableCode / unreadableHint
```

The `incomplete[]` / `cause` pairs are the v5.4.0 unknown-as-fact work (#941/#937/#920). **A derived
file built from this source can distinguish "no live session" from "could not establish whether
there is one" for free**, because the source already models the difference.

## The gap, precisely

`FLEET.md` carries **identity and no state.** Its whole per-project line is:

```js
const bits = [p.engineId || 'no engine', p.path];
if (p.archived) bits.push('ARCHIVED');
fleetLines.push(`- **${p.name}** — ${bits.join(' · ')}`);
```

Name, engine, path. Every field in the block above is in hand at the moment that line is written,
and all of it is dropped.

**That single omission is why the Master cannot tell what anything is doing.** Not a missing
subsystem — a fleet map that lists doors without saying which rooms have anyone in them.

## Design

### 1. Two zones, one rule

> **Derived state is regenerated and never remembered. Observed state is remembered and never
> regenerated.**

Everything follows from that. Derived can't go stale because it isn't stored as belief. Observed is
the only thing worth persisting, because it is the only thing nothing else can reconstruct.

- **Derived** — anything TangleClaw can recompute: branch, HEAD, dirty, live session, version,
  open issues, last wrap, governance. TC writes it, stamps it, marks it do-not-edit. The Master
  never writes here and never quotes it as memory.
- **Observed** — the Master's own judgments: why a project is stuck, a cross-project dependency
  nobody recorded, a pattern across three repos. TC never writes here.

### 2. `FLEET.md` grows state

Same file, same lifecycle, same do-not-edit stamp. Per project, from data already in hand:

```
- **TangleClaw** — claude · v5.5.0 · main · clean · session LIVE since 19:36 · last commit 2 hours ago
- **Notse** — claude · v0.4.1 · feat/x · DIRTY · no live session · last commit 3 days ago
- **Kobold** — antigravity · version unknown (could not read the project directory — EACCES)
```

The third line is the point. It is what the unknown-as-fact family bought, and it must survive into
this file rather than being flattened to a guess or omitted.

### 3. A per-project status document — `.tangleclaw/STATUS.md`

The operator's idea, and it earns its place for a reason `FLEET.md` structurally cannot cover: it
lives **in the project**, so it survives a fresh clone, a machine move, and a Master that has been
wiped. `FLEET.md` is fleet-level and lives only in the Master's home.

- **TangleClaw writes it. The project's session never touches it.** This is what resolves the
  tension in "no push from the wrap, but always kept updated" — nobody has to *remember*, because no
  agent is involved.
- Written on the same triggers TC already has: session launch, session wrap, project sync.
- Carries the project's own view: current work item, open issues it is blocking or blocked by,
  last wrap summary, active plan — sourced from `.tangleclaw/memories/`, `project.json`, and git.
- **Tracked-ness is not TC's call.** `.tangleclaw/` is tracked in some projects (Notse) and
  gitignored in others (TangleClaw's own clone). `STATUS.md` inherits whatever that repo already
  decided, exactly as `memories/` does today.

### 4. Drift becomes a computed number, not an instinct

The operator asked for the Master to be *self-aware* that its memory drifts. Asking an agent to
remember to be humble is not a mechanism. This is:

- Every derived file carries `generated-at`.
- Every Observed note carries `observed-at` for the project it concerns.
- At startup, TC compares them per project and **states the delta in the prime**:

```
Your notes on Notse are from 3 days ago. Its derived state has changed 11 times since —
branch moved feat/a → feat/b, 4 commits, one wrap. Re-read before relying on them.
Your notes on Kobold are current.
```

Staleness stops being an invisible hazard and becomes the opening briefing. This is the single most
important part of the spec, and it is the part with a real incident behind it: on 2026-08-16 the
TangleClaw-Roadmap session held a "blessed next train" of five issues that had all closed two days
earlier, and confidently directed a session at shipped work. A Master does that across the whole
fleet at once.

### 5. The write boundary

The operator's correction stands: a Master that cannot act is a dashboard. The line is narrower
than "don't write to projects":

> **The Master may ACT on a project. It must not AUTHOR a project's beliefs about itself.**

- **Allowed:** edit code, send Medusa messages, update plugins, open PRs, run commands. All
  visible, all attributable through git, all things the project's session can see and undo.
- **Forbidden:** writing another session's `MEMORY.md`, handoff notes, plans, or `STATUS.md` —
  the files a session reads as its own truth. Two authors there and nobody can tell whose belief is
  whose. This is the same rule the global Cross-Session Write Boundaries section already states for
  advisor/builder pairs; the Master is that pattern at fleet scale.

**One hard mechanism constraint, not a preference:** two sessions on one clone share a single git
HEAD. If the Master writes to a repo with a live session, a branch switch on either side yanks the
other's work mid-task. So:

| Target | Rule |
|---|---|
| Project with **no** live session | Master may write directly. |
| Project **with** a live session | Master goes **through** the session (Medusa), never around it. |
| Liveness **could not be established** | Treat as live. Refuse, and say why. |

TC already knows which case applies — that is the `session.active` / `session.cause` tri-state.
This is enforceable in code, not just in rules, which is what `MASTER_ENABLED_ACCESS_LEVELS`
requires before a tier above `read-only` may ship (#755).

## What "Master wrap" actually runs

The default pipeline is 14 steps (`lib/wrap-default-pipeline.js`). Mapped against a target with no
working tree:

| # | Step | Kind | Master |
|---|---|---|---|
| 1 | open-pr-check | pr-check | **skip** — no repo |
| 2 | changelog-update | ai-content | **runs**, retargeted to `memory/CHANGELOG.md` |
| 3 | version-bump | version-bump | **skip** — the Master has no version of its own |
| 4 | learnings-capture | ai-content | **runs** → `memory/NOTES.md` |
| 5 | learnings-db-write | learnings-db-write | **runs** — under a `master` scope (ruling 1) |
| 6 | rule-proposal | rule-proposal | **runs** — the Master has Hard rules (`kind='master'`) |
| 7 | next-session-prime | priming-roll | **runs** |
| 8 | features-toc | features-toc | **skip** — no `FEATURES.md` |
| 9 | project-map | project-map | **skip** — no tree to map |
| 10 | index-describe | index-describe | **skip** — no index |
| 11 | memory-update | ai-content | **runs** — the core step |
| 12 | commit | commit | **skip** — no working tree |
| 13 | continuity-write | continuity-write | **runs** — to `~/.tangleclaw/master/continuity/` (ruling 2) |
| 14 | apply-pr-resolutions | pr-merge | **skip** — nothing to merge |

**Seven run, seven skip with a reason** (steps 5 and 13 were the two open rulings; both now run). Every skip surfaces in the wrap drawer as
`skipped` with its reason, using the mechanism at `lib/wrap-pipeline.js:32` — so an operator reading
a Master wrap sees exactly which of the fourteen did not apply and why, rather than a shorter list
that silently implies the rest succeeded.

**This satisfies the engine-agnostic rule by construction.** Which steps ran and which skipped is
mechanical and identical on every engine; only the prose quality of the three `ai-content` steps
varies with engine strength.

**Recommendation on the button, unchanged from #768:** ship Kill first. Wrap ships once this spec is
ratified, and when it does it is labelled *Wrap* honestly, because it is the same pipeline.

## What Master startup does

1. `refreshMasterIdentity()` — already exists, already runs on boot (`lib/master.js:603`).
2. Regenerate `FLEET.md` **with state** (§2).
3. Compute the drift delta per project (§4) and render it into the prime.
4. Leave `MEMORY.md` / `NOTES.md` / `CHANGELOG.md` untouched.

Steps 1 and 4 are shipping today. Steps 2 and 3 are the build.

## Rulings — decided 2026-08-16

1. **`learnings-db-write` (step 5) — RATIFIED: a `master` scope.** Fleet-level learnings are
   queryable without polluting any single project's learnings.
2. **`continuity-write` (step 13) — RATIFIED: `~/.tangleclaw/master/continuity/`.** The same shape
   in the Master's own home, which keeps the wrap drawer's continuity view working for the Master.
3. **Master memory survives a kill — RATIFIED.** Observed persists because it is expensive
   accumulated judgment; Derived is regenerated in the same breath as the next start. A kill ends
   the session, not the memory.
4. **The Master is a Medusa participant — RATIFIED, with send-only SUPERSEDED.** The draft
   recommended send-only until #755. The operator raised a use case that send-only cannot serve:
   asking the Master to work with a project session toward consensus on a ruling, purely to get
   more reasoning onto the question. That requires receive.

   The hole being guarded was never "receiving" — it was **any session addressing the Master
   unprompted** and steering the fleet through it. So the rule is scoped by who opens the channel,
   not by direction:

   > **The Master may receive, but only inside an exchange the OPERATOR opened** — a named
   > counterpart, a stated question, a defined end. Never an open inbox.

   `HOWTO.md` currently tells the Master *"you observe through the activity feed — you are not a
   participant."* That line is now wrong and must be updated in the same change that enables this.

5. **Operator-convened consensus between the Master and a session — RATIFIED, with two
   constraints that are part of the ruling, not commentary.**

   **(a) The consensus is never the ruling.** The Master's output is a recommendation to the
   operator. The session still authors the decision into its own files. This is §5's "act, don't
   author" holding exactly as written — the Master contributes reasoning, not a record.

   **(b) Agreement between the two is not two pieces of evidence.** The Master's context about a
   project is largely DERIVED FROM that project, some of it downstream of the session itself, so
   agreement may be correlated rather than corroborating — while reading to the operator like
   confirmation. Therefore: the Master's role in these exchanges is to **challenge**, and the
   record must state what was disagreed about and how it resolved. Where there was nothing to
   disagree about, it must say that too. "We agreed immediately" and "we stress-tested it and it
   held" are different inputs to an operator's decision and must not render identically.

## Where this could be wrong

Stress-testing my own proposal, because nobody else has yet:

- **`FLEET.md` grows without bound.** 25 projects × a state line is fine; 100 is a context tax the
  Master pays on every start. Mitigation: `FLEET.md` stays one line per project and per-project
  detail lives in each project's `STATUS.md`, read on demand. That is why §3 is not redundant
  with §2 — but it does mean the Master must be told to go read, and a Master that never does is
  back where it started.
- **A silently-failing writer is worse than no file.** If TC fails to write `STATUS.md`, what
  remains is a stale file that reads as current. It needs the same `generated-at` +
  could-not-establish honesty as everything else, and a stale-stamp check at read time — otherwise
  this spec reintroduces the exact bug it exists to prevent, one level down.
- **The drift delta is only as good as `observed-at`.** If the Master writes notes without stamping
  which project and when, §4 computes nothing. That stamping has to be structural — a note format
  TC can parse — not an instruction the agent is asked to follow.
- **"Act, don't author" is a bright line in prose and not yet in code.** Until #755 gives the
  access-level control real enforcement, this whole boundary is instructional. That is precisely
  what `MASTER_ENABLED_ACCESS_LEVELS = ['read-only']` exists to prevent shipping, and it is why
  #755 sequences before any of this becomes operative.

## Suggested build order

Each of these is independently useful, and the first two ship value with no rulings needed.

1. **`FLEET.md` grows state.** ✅ **DONE 2026-08-16** — issue #950, branch
   `feat/950-fleet-map-state`. The Master goes from "these projects exist" to "here is what each is
   doing".

   **Correction to this spec's own estimate:** it said "in one function", and that was wrong.
   `refreshMasterIdentity` is fully synchronous and runs at server boot, while the state the map
   needs comes from `git.getInfo` (several `execSync` spawns per repo on a cold cache) and an async
   tmux snapshot — putting that on the boot path is the event-loop hazard `lib/dir-scanner.js`
   exists to prevent (#883/#884). So it is a split: a pure renderer `buildFleetMap`, the sync path
   writing an identity-only map that DECLARES itself identity-only, and an async `refreshFleetMap`
   riding the enriched list `listProjects` already builds. The estimate was wrong because it was
   made from what the file needed rather than from what its writer could afford.
2. **Drift delta in the prime.** Needs a parseable `observed-at` convention in `NOTES.md` first.
3. **`.tangleclaw/STATUS.md`** — a new TC-maintained project-local file.
4. **Master wrap pipeline variant** — rulings 1 and 2 are decided, so this is gated only on #755.
5. **Medusa send + operator-scoped receive** (rulings 4 and 5), including correcting the now-wrong
   `HOWTO.md` line that tells the Master it is not a participant.
