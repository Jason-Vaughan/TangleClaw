# #1885 Provenance watermarks

## Requirements confidence: High

R25 answered every open question. The problem, success criteria and scope can each be stated in
one sentence, and ADR 0019 records the contract.

- **Problem:** across many projects and instances, you cannot tell which TangleClaw project
  generated a given file.
- **Success:**
  - A project that opts in gets exactly one provenance line on each of five private generated
    files, in that file's comment syntax.
  - Regeneration replaces the line and never stacks a second one.
  - Opting out, or the file becoming tracked, removes the line at the next regeneration.
  - With the setting off (the default), every generated file is byte-for-byte identical to today.
- **Out of scope** (ADR 0019 §2):
  - whole-file `CLAUDE.md`;
  - managed-block carriers, including inside TangleClaw's own block;
  - git hooks, Master files and inactive notices;
  - seeded or user-owned files;
  - vendor files, binaries, JSON, state, logs and secrets;
  - Caddy integrity headers and plists;
  - any global setting;
  - any `tc` mutation verb;
  - any fleet sweep.

## Discovery findings (verified at 5f74a343)

1. **Provenance headers already exist, and one of them is load-bearing.**
   `GENERATED_HEADER_MARK = 'Generated by TangleClaw'` is defined at `lib/engines.js:253` and again
   at `lib/wrap-steps/_tc-owned-paths.js:690`. Whole-file engine configs carry it on line 1
   (`# CLAUDE.md — Generated by TangleClaw`, plus the codex and aider configs).
   `retireInactiveEngineConfig` (`engines.js:373`) and `_looksGenerated` (`_tc-owned-paths.js:699`)
   each treat "that sentence in the first 3 lines" as permission to **overwrite the whole file**.
   So a watermark must never (a) push that header past line 3, or (b) let an override template
   write that sentence into a file TangleClaw does not own. Otherwise a user file could later be
   clobbered on engine switch.
2. **Other ownership stamps already exist:** `# TC-OWNED-HOOK:` (git hooks, `git-hooks.js:23`,
   `control-hooks.js:60`), the sha256-hashed Caddyfile header (`caddy.js:35,47`, with an integrity
   check at `:672`), and `<!-- Generated by TangleClaw … do not edit -->` on the Master memory
   files (`master.js:815,1412`). These are machine-read markers, not provenance. The watermark
   must sit beside them and must never be allowed to replace them.
3. **There is no central writer.** About 70 `fs` write sites write directly. `lib/staged-write.js`
   `writeAtomic` is used by only 2 of them.
4. **Comment syntax:** `MANAGED_BLOCK_COMMENT_FORMS` (`engines.js:150`) covers markdown, yaml and
   toml, keyed by engine profile syntax. Nothing maps file kinds to syntax. `_inactiveNotice`
   (`engines.js:280`) is the precedent for a per-syntax renderer.
5. **There is no template helper.** The single-token replacer `_resolveHookPlaceholders`
   (`engines.js:3044`) is the precedent for a bounded substitution.
6. **Null does not fall back to the default today.** `store.config.load()` does
   `{...DEFAULT_CONFIG, ...parsed}`, so a stored `null` beats the default (`store.js:574`,
   `project-config.js:269`). The operator's reset semantics therefore need a resolver of the
   `resolveReleaseMode` / `resolvePasteRules` shape (`project-config.js:308,368`) that returns
   `{value, source: 'default'|'override'}`.
7. **Settings surfaces:** the global modal is `openGlobalSettings` (`public/ui.js:3437`); the
   toggle to copy is `gsStripAiCoauthors` (`:3541`), the closest attribution-flavoured neighbour.
   The per-project modal is `openSettings` (`:1616`). The per-project precedent for "blank means
   default" is `versionFilePath` (`:1707`, normalized to null at `lib/projects.js:3543`). The API
   is `PATCH /api/config` (`server.js:1849`, `allowedFields` allowlist) or
   `PATCH /api/projects/:name` (`PROJECT_UPDATE_VALIDATORS`, `lib/projects.js:2778`). A bounded
   nested object has a precedent in `medusaWatchdog.validatePatch` (`lib/medusa-watchdog.js:167`).
   There is no `tc config` verb. `tc capabilities` entries are built in `server.js:4710`.
8. **`PATCH /api/config` has no caller check.** `store.js:1524` notes that agent sessions reach
   it on loopback. See Q5.
9. **ADR 0013 applies.** The surface that offers the setting must say where it does not take
   effect. OpenClaw has no config file (`ENGINE_CONDITIONAL_SETTINGS`, `engines.js:1357`, mirrored
   by `tcSettingDisposition` with a parity test).
10. **A gap noticed in passing, not in scope:** `docs/configuration-reference.md` omits
    `stripAiCoauthors`, and no test checks docs against config keys. I suggest a separate
    `[docs]` issue.
11. **Key naming:** config keys are camelCase (`stripAiCoauthors`, `featureIndexEnabled`). The
    issue's `embed_provenance_watermark` would be the only snake_case key. This plan uses
    `provenanceWatermark` (see Design).

## Design (per R25 and ADR 0019)

**One leaf module, one writer (A3, A6).** `lib/provenance.js`, modelled on `lib/managed-block.js`:

- **`REGISTRY`** is frozen and **keyed by an explicit `surfaceId` that each writer passes**
  (R25.9).
  - It maps each id to `{ syntax, placement, eligibility }`.
  - It may assert the expected path shape as a sanity check, but the id is the only grant.
  - Nothing is inferred from an extension, a path pattern, or "TangleClaw wrote it".
- **`COMMENT_FORMS`** covers markdown (`<!-- … -->`) and hash (`# …`). v1 needs no others.
  - An unknown syntax is refused, matching the precedent at `engines.js:164`.
- **`renderLine(syntax, text)`** emits a line carrying the sentinel `tangleclaw:provenance`, e.g.
  `<!-- tangleclaw:provenance Built by TangleClaw (Project: X) -->`.
  - Replace and remove find the line by the sentinel, never by the free text.
- **`applyProvenance(surfaceId, content, ctx)`** is pure.
  - It removes any sentinel line, then inserts one only if the project's setting is enabled **and**
    the surface is eligible.
  - It is idempotent.
  - When the setting is off or the surface is ineligible, it returns the content without the line.
  - With the setting off, content that never had the line comes back byte-identical.
- **`writeOwnedFile(absPath, surfaceId, content, ctx)`** is the single shared writer.
  - It calls `applyProvenance`, then writes atomically through `staged-write.writeAtomic` by default.
    A surface that declares `write: 'in-place'` (the codex and aider carriers) is written in place
    instead, which keeps the file's mode and follows a symlink.
  - Only the five registered writers are switched to it.

**One tracked-carrier predicate (R25 Q2, ADR 0001 paired state).**
- Eligibility for `codex-config` and `aider-config` is decided by `_carrierIsCommitted`
  (`engines.js`), the existing #1619 git check.
- That function is exported or passed in, and never re-derived.
- The same call decides insertion and removal. A private carrier that later becomes tracked loses
  its line at its next regeneration.
- There is a test for that transition.

**Bounded template (A4, R25 Q6).**
- The default is `Built by TangleClaw (Project: {project})`.
- The override is at most 120 characters, and its placeholders are only `{project}` and `{engine}`.
- Validation refuses:
  - unknown `{…}` tokens;
  - control characters and newlines;
  - comment terminators (`-->`, `*/`);
  - the reserved markers: `Generated by TangleClaw`, `TangleClaw: INACTIVE`,
    `BEGIN:`/`END:tangleclaw`, `TC-OWNED-HOOK`, `tangleclaw:provenance`, `TANGLECLAW:PRIMING-ROLL`,
    `tangleclaw-state`.
- **The substituted values get the same treatment as the literal text** (R25 Q6).
  - The rendered line is checked after substitution.
  - A project or engine name that would end a comment, add a line, or produce a reserved marker
    is neutralized:
    - Control characters become spaces. `<` and `>` become `‹` and `›`, and `/*` and `*/` are split.
    - Each value is capped at 80 characters.
    - If the whole rendered line still contains a reserved marker or a delimiter, it renders as the
      fixed text `Built by TangleClaw`, with no values. [DECISION, made during chunk 01: this
      replaces the plan's earlier "default template with `{project}` escaped". The default template
      still includes `{project}`, so it could not be guaranteed marker-free.]
  - Tests cover adversarial names across every supported syntax, in both markdown and hash forms.

**Per-project config (R25 Q4, Q5, Q8).**
- `provenanceWatermark` goes in `DEFAULT_PROJECT_CONFIG` with the value `null`, following the null-default precedent that `releaseMode` sets; the resolver reads `null` as off. Its settable shape is `{ enabled, template }`
  (`lib/project-config.js`).
- It is validated by a bounded-merge row in `PROJECT_UPDATE_VALIDATORS` (`lib/projects.js:2778`)
  that refuses unknown keys (ADR 0013).
- It is written through the existing `PATCH /api/projects/:name` route under its existing threat
  model.
- `resolveProvenance(projectConfig)` returns `{ enabled, template, source }`. A missing, `null` or
  `''` template gives the default with `source: 'default'`, which is the operator's reset.
- There is no global key, no `tc` mutation verb, and no claim that agents are authorized.
- A read-only `tc capabilities` entry reports enabled or disabled and the eligible surfaceIds,
  never a path (ADR 0019 §5).

**Migration (A5, R25 Q7).**
- There is no sweep.
- Enabling, a template change, disabling, and an eligibility change all take effect only at each
  file's own next natural regeneration.
- The UI and the docs say that propagation is gradual.
