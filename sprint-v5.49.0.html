📖 Plain-English Summary — What Sprint v5.49.0 Accomplished & Why It Matters Written for operators, stakeholders & non-specialist readers

Making Every AI Engine Setting Tell the Truth Across Claude, Codex, Gemini, Aider & OpenClaw

TangleClaw coordinates multiple AI coding engines (Claude Code, OpenAI Codex, Google Antigravity/Gemini, Aider, and OpenClaw), each with different capabilities. Before v5.49.0, several settings screens and startup paths quietly showed controls that did nothing for the selected engine, wrote raw Markdown into YAML config files, or hid a single test failure on our remote test cluster. Sprint v5.49.0 (“Engine settings that tell the truth”) closed 12 issues across 9 pull requests in three major areas:

1. Honest Engine Controls & Live Inventory (`#1268`, `#1269`, `#1264`, `#764`, `#1276`)

Project settings now ask a single source of truth whether an option actually applies to the chosen engine: plugin-governed projects clearly explain that CLAUDE.md is managed by the Prawduct plugin (#1268, #1276), engines without startup-rule injection show an immediate warning when selected (#1269), connection-backed OpenClaw profiles display their launch-mode controls accurately (#1264), and new read-only API endpoints (GET /api/engines/inventory) expose every engine’s true runtime capabilities and installed binary status (#764).

2. Safer Engine Launches, Model Checks & Master Configs (`#738`, `#1113`, `#2220`, `#2278`, `#260`, `#1085`)

First-time setup no longer pre-selects an AI engine that isn’t installed (#738), saving an unknown defaultEngine is rejected with a clear 400 error (#2278), Claude’s artifact auto-open env variable is properly declared in its engine profile (#1113), Codex model pickers cache display metadata from ~/.codex/models_cache.json (#2220) and warn before launch if a chosen model is unsupported (#260), and Master identity files serialize valid YAML for Codex (.codex.yaml) and comments for Aider (.aider.conf.yml) instead of raw Markdown (#1085).

3. 100% Remote Test Pool Parity (`#2742`) & 2-Wave 10-Lane Autonomy

We root-caused why 1 of our 150 Medium test files (test/reset-admin-store.test.js) produced corrupted JUnit XML on our remote container cluster: its test hook was accidentally swallowing binary V8 event frames written to process.stdout by Node 22’s child test runner. A 2-line fix brought both Stage 3 (5,848 tests) and Stage 4 (5,759 tests) to 100% green on the 4-machine Testament pool.
